# 文献定向与机理锚定

> 通用执行纪律（增量返修 / 缩比预估 / 分段落盘 / 方法标记 / 返修只动清单内）见 `../_references/stage_discipline.md`。
> 本阶段适用：一（增量返修，含 1.1 探针复用）。
> 探针/量测脚本要复用（通用纪律 一·1.1）：本轮写的取证/量测脚本一律留在 `_tmp/`
> （另有散落的在 `tmp/`，两个都要看）；下一轮开工第一步 = `ls _tmp/ tmp/` → 把上一轮
> 为同一批对象写过的脚本先原样重跑（秒级，确认数在当前版本里还成立）→ 只对本轮新出现或改过
> 的对象写新脚本。别每轮从零重写 —— 全链 776 个自写脚本里 **683 个（88%）只被用过一次**
> 就再也没人碰。复用探针 ≠ 跳过复核：探针只是取证手段，判定仍逐条对着当前版本做。

本阶段是完整工作流的第 2 步，位于赛题分析（2Modeling-design）之前。它不建立正式模型、不写代码、不写论文；它只回答两个问题：

1. 每个子问题，近年的高相关文献用什么算法/模型族、为什么——给建模手指出方向。
2. 每个子问题背后的领域机理基线是什么——即"真正的因果主变量/主导物理过程"是什么，给建模与评审一个不依赖数据拟合的外部锚点。

这是本工作流的关键新增之一：建模最容易"纯数据驱动跑偏"（如把衍生变量 c_X 当主变量、把机理主变量挤成不显著）。有了文献机理基线，后面 3Modeling-review-gate 就有依据拦截这类错误。

## 数学建模规范参考

如需题型/机理判断，读取 `../_references/math_modeling_norms.md` 的"模型大分类与选型速查""机理/动力学类模型""预测类模型"等小节。

## 必须产出

在当前工作目录的 `reports/` 下创建 `LITERATURE_DIRECTION.md`：

- 赛题主题与领域关键词
- 逐子问题的「推荐建模方向表」，每行包含：
  - 子问题编号
  - 主流模型族 / 算法（含近 3-5 年进展）
  - 领域机理基线（该问物理/业务层面真正的主变量、因果方向、主导效应）
  - 2-4 条真实文献（标题、作者/年份、期刊或 DOI、一句话为什么相关）
  - 可检索的英文/中文关键词
- 明确的"应规避的常见错误"清单（基于文献与机理，如"某衍生量不应被当作因果主变量"）

## 工作流程

### Step 1：轻量拆题与定检索主题

通读题面 `request/problem.md` 与附件说明。只把题面明确编号的顶层问题当作子问题（问题一/二/…）。对每个子问题，提炼出检索主题三元组：(① 对象/场景，② 要建的关系/决策，③ 数据类型)。不要在此阶段写正式模型。

> 检索主题与关键词完全由本题领域决定，下面例子只演示"怎么提炼三元组"，不构成任何领域的固定模板。
>
> 示例（仅示意检索思路）：某体检类题的问题二，对象是"体检人群按某指标分组 + 定随访时点"，要建的关系是"到某事件的时间 vs 指标 + 时点风险权衡"，数据是纵向重复测量 + 删失 → 检索词可能覆盖 `survival/time-to-event`, `longitudinal`, `coverage/attainment`, `timing/interval optimization`。换一个题（如经济预测、资源调度、物理机理），对象、关系与关键词完全不同——按你的赛题重提炼。

### Step 2：逐子问题 WebSearch / WebFetch

对每个子问题执行检索。优先顺序：

1. Claude Code 的 WebSearch / WebFetch 工具（若当前运行环境可用）。
2. 不可用时回退到 Bash + python 请求公开接口：CrossRef API、PubMed E-utilities、arXiv API（如 `https://api.crossref.org/works?query=...&rows=5`）。

中文文献支线：题面与领域在国内的，除英文文献外**再补 2–3 篇近年中文核心刊**文献。下面这些入口都实际跑通过（每路都真发过请求）：

- 维普（主力，唯一能"按关键词发现"中文核心刊的源）：`https://www.cqvip.com/search?k={关键词}` —— 未登录可直接拿题录（题名/作者/期刊/年/期/页/摘要/关键词/DOI/北大核心标注）。详情页 URL 必须从结果页 HTML 里抠（带 sign），**不能自拼**。
- Crossref / DOAJ（公开 API，兜底）：`https://api.crossref.org/works?query.bibliographic={中文关键词}&rows=5`；OA 刊可加 DOAJ。
- 已知题名/文件名 → 补全题录：手机知网 `https://wap.cnki.net/touch/web/Journal/Article/{15位文件名}.html`（页内 `__NUXT__` 就是整条 JSON，字段最全）、知网空间 `https://www.cnki.com.cn/Article/CJFDTOTAL-{文件名}.htm`；期刊官网（农业工程学报 `tcsae.org`、化工学报 `hgxb.com.cn`，后者有 sitemap 可批量枚举）。
- **明确不要试**（全都拿不到，纯浪费时间）：知网自有检索（kns 新版/高级/navi 都跳滑块 `blockPuzzle`）、手机知网检索 API（403）、知网空间结果接口（0 条/超时/500）、万方、百度学术、超星、掌桥、X-MOL、NSTL。批量时限速，把失败当常态，别死磕。
- 中文条目同样要真实可核验（能给 DOI / 期刊 / 年之一）并如实标注语种；**不许为"看起来有中文"而编造**。

检索要点：

- 以"近 3-5 年"为主，兼顾一两篇经典奠基文献（便于评审与写作引用）。
- 每个子问题至少确认 1-2 条真实、可核验的文献（能拿到 DOI/期刊/作者之一），不要编造。
- 对"机理为主"的子问题（物理/医学/工程机理题），额外检索该领域的综述或权威指南，提炼机理基线。

WebFetch 失效的应对（重要）：本运行环境的 WebFetch 常因"Unable to verify if domain … safe to fetch"（域名安全校验不可用）对所有外部域名失败，而 WebSearch 可用。若 WebFetch 连续失败：
1. **不要反复对多个 URL 重试 WebFetch**（浪费时间）；
2. 改用 WebSearch 按"作者/标题/年份 + 主题词"的精确串去拿结果片段来核验；
3. 需要确认某 DOI 的元数据（作者/期刊/年份）时，用 **Bash + python 请求** `https://api.crossref.org/works/<DOI>` 或 PubMed E-utilities `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esummary.fcgi?db=pubmed&id=<pmid>&retmode=json`（公开接口，无需代理）。
仅在确实需要网页正文时才再试 WebFetch，失败就换上面两条路。

### Step 3：提炼机理基线（关键）

对每个子问题，在报告中明确写出：

- 真正的主变量 / 主导机制（例：染色体非整倍体 → 相应常染色体读段过量/Z 值；细胞动力学 → 主导生化过程）
- 因果方向与主要混杂/调节（例：孕期增重使 BMI 与孕周正相关，需控制）
- 数据/业务上允许的主变量代理（哪些量可以直接测、哪些是估计/衍生量）

这一步是后续 3Modeling-review-gate 判断"特征选择是否合机理"的裁判依据，必须写得让评审员能据此判 PASS/FAIL。

### Step 4：推荐建模方向

对每个子问题，结合文献与机理，给 1-3 个建模算法族候选并说明取舍。特别提示两类"方向性选择"：

- 若问题涉及"到某阈值的时间 / 达标时间 / 删失"，提示优先考虑 生存分析 / 保障率（coverage）约束的优化，而非把平均风险当唯一目标。
- 若问题涉及测序/测量类数据的判别，提示考虑 对测量噪声的校正（如 Z 值对 GC/读段深度的回归去偏），而非直接裸用原始特征。

### Step 5：写报告

按"必须产出"格式写 `reports/LITERATURE_DIRECTION.md`。开头给一句总括（"本赛题可归为 X 类，各问分别宜用 Y/Z…"），逐问给方向表。末尾列"应规避错误清单"。

## 阶段边界

- 不写论文正文；不生成 `paper/`。
- 文献必须真实可核验；宁缺毋滥，检索不到就写"文献有限，机理依据见 X 综述/常识"，不要编 DOI。
- 产出只作为 2Modeling-design 与 3Modeling-review-gate 的输入参照，不替代它们的正式产出。
