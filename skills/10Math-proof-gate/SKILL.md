# 数学论证门禁（对成稿论文的深度审计）

> 通用执行纪律（增量返修 / 缩比预估 / 分段落盘 / 方法标记 / 返修只动清单内）见 `../_references/stage_discipline.md`。
> 本阶段适用：一（增量返修，含 1.1 探针复用）、五（返修只动清单内）、六·6.1（先落骨架再深挖）。
> 探针/量测脚本要复用（通用纪律 一·1.1）：本轮写的取证/量测脚本一律留在 `_tmp/`
> （另有散落的在 `tmp/`，两个都要看）；下一轮开工第一步 = `ls _tmp/ tmp/` → 把上一轮
> 为同一批对象写过的脚本先原样重跑（秒级，确认数在当前版本里还成立）→ 只对本轮新出现或改过
> 的对象写新脚本。别每轮从零重写 —— 全链 776 个自写脚本里 **683 个（88%）只被用过一次**
> 就再也没人碰。复用探针 ≠ 跳过复核：探针只是取证手段，判定仍逐条对着当前版本做。

## 定位与边界

本阶段是 9Paper-writing 之后、11Cross-question-check 之前的门禁（链路：write → mathproof → cross → rubric → fix → format → verify → demo；内容判据排在 `14Layout-and-format` 之前）。上游 4review/review-math 审的是建模报告（代码之前），管不到 9Paper-writing 才写出来的成稿措辞；本阶段补上这一段：对已成稿的论文文本，逐条审查带数学标签/强声称的对象是否满足"证明-措辞契约"（见 `skills/_references/math_modeling_norms.md`）。

- 只审不改：本阶段**绝不修改 paper/** 任何文件。发现缺陷 = 在 `MATH_PROOF_REPORT.md` 写 REVISE + 逐条修改清单，退回 9Paper-writing 由 write 补推导或降级措辞。
- **题型无关，绝不制造证明**：只对确实以"定理/命题/引理/证明/性质"命名或做了强解析声称的对象介入；论文里没有这类对象（纯数据/评价/启发式题）→ 直接 APPROVED。**禁止**主动把普通结论升级成命题来"显得有数学"。
- 允许的四种处置：每一条目 = `OK`（有推导、前提显式、独立复核通过）／`NEED_PROOF`（推导缺失或不足 → 回 write 补）／`NEED_REPAIR`（内核正确但字面过强/前提不足 → 回 write 把该条改写为带修正项与完整前提的精确命题，保留命题框架，如把"严格过原点"改成"落在 $m=H/d$ 的 $O(|\varepsilon_k|)$ 邻域，$\varepsilon_k=-\bar\varphi/\pi+\delta_k/\pi$，数值界见…"；这是大多数"看似为假"的半解析断言的默认处置）／`NEED_DOWNGRADE`（数学内核确无可挽救 → 才降级为"数值观测/经验断言"，属末位选项，报告中必须写明"为何无法修复为精确命题"）。

## 输入

- `paper/main.tex` + `paper/sections/*.tex`：只读源码，逐字审查。
- `reports/RESULT_AUDIT_REPORT.md`、`reports/RESULTS_REPORT.md`：确认真实结论表述，防止门禁要求"证明不存在的东西"。
- 若需数值交叉探测，可读 `code/` 与 `code/outputs/*.json`（只读，不改、不重算）。

## 工作流

### Step 0：审计范围（第 2+ 轮增量，省时省 token）

- 先落骨架（§六·6.1）：开工第一步就写 `MATH_PROOF_REPORT.md` 与 `.verdict.json`（`status=UNVERIFIED`、`issues: []`），**不要等逐条判完再写**。
  骨架的报告末尾「整题门禁裁决」那一行写 `（待填）` —— **不要写 `APPROVED`/`REVISE_HARD`/`REVISE_SOFT` 里的任何一个**（驱动只认状态词、不认"（占位）"那样的小注 ⇒ 与 `UNVERIFIED` 侧车撞成"裁决冲突"⇒ 整链停机）。本阶段的独立复推子 agent + 数值探测极容易吃光整段时间；产物留到最后写，一旦跑到没气现场就是一片空白——驱动只报「阶段未成功完成：failed」，读不出任何结论。骨架是占位不是结论，每判完一批条目必须回填，`## 整题门禁裁决：…` 判词行只有在全部条目真的判过之后才能定型。
- 首轮：全文盘点（Step 1）+ 全部条目判定。
- 第 2+ 轮（本轮前已存在 `reports/MATH_PROOF_REPORT.md`，且 `cache/` 有上一版 paper 快照）：先定位改动——
  `ls -dt cache/*_paper | head -1` 找最新快照，`diff -r <快照>/paper paper/` 列改动文件/行。
  - 改动面小（各文件 < ~60%）→ 只重审 (a) 上轮全部 flagged 条目所在小节（**必须逐条复查**，防"改了却没改对"）+ (b) diff 命中行；其余已 OK 条目不再整条重推。
  - 改动面大 / 无快照 → 回到全文。
- 数值交叉探测**写成 `_tmp/*.py` 再跑**（避免内联 `python -c` 的引号/编码反复语法错）；scratch 一律放 `_tmp/`，**不留在项目根。
- 探针要保留、下轮先复用**（省掉重复劳动）：`_tmp/` 里的脚本
  **不要删**（它们住 `_tmp/` 已经不污染项目根了）。第 2+ 轮开工时**第一步**就是：
  1) `ls _tmp/`（+ 看上一轮 `reports/MATH_PROOF_REPORT.md` 的"扫描范围/断言清单"）找出上轮为
     哪些条目写过探针；2) **先原样重跑它们（秒级），确认那些数在当前正文里仍成立；
  3) 只对本轮新出现或改过的声称写新**探针。别每次从零重写一遍 —— 一轮 8 个
     探针脚本、138 次 PowerShell、耗时 34.6 分钟，其中大半是重复劳动。
  复用探针 ≠ 跳过复核：探针只是**取证手段，判定仍要逐条对着当前正文做（探针重跑结果与
  正文对不上时，以正文为准并记为 NEED_REPAIR）。
- 这条是所有阶段的通用纪律**，完整版见 `../_references/stage_discipline.md` 的「1.1 探针与中间工具」。

### Step 1：盘点数学对象（措辞清单）

用 Grep 对 `paper/**`（`.tex`）扫以下两类信号，产出断言清单：

- 标签词：`定理|命题|引理|推论|性质|证明|证毕`
- 强解析声称（常在摘要/引言/结论句里，未带标签但等价于命题）：`证明了|已证|严格相同|严格一致|恒成立|精确成立|正交|一阶无偏|无偏|可由.*推出|由.*(解析|恒等|对称)可得`

对每个命中记录：文件/行/原句。误报不纳入（如"得到证明支持""经验上成立""数值上一致"），但要警惕摘要宣称证明而正文无推导的脱节点。

### Step 2：逐条判定（对照"证明-措辞契约"）

对清单中每条 A 类（带标签命题）与 B 类（无标签但等价强声称），读其上下文小节，检查：

1. 推导存在：该断言下方（同小节、引用的式之前/后）是否有等式级推导（LaTeX `equation/align/\[…\]` 或行内/块级 `$…$`），足以从前提/定义推出该结论？"自然语言叙述 + 图/表/合成谱/仿真" 不算推导。
2. 前提显式：推导依赖的条件（如实反射系数分支、慢变、无相位跳变、整周期、均匀加权、常数系数）是否被写出来？推导里用到的每个"显然成立"是否真的成立？
3. 理想化余项：若结论依赖整周期积分正交/均匀加权/全谱平均这类理想化，是否给出了理想化不成立时的一致余项上界（量级即可）或数值上界？没有 = NEED_PROOF（补余项）或 NEED_DOWNGRADE（把"恒等于零/严格无偏"改成"有界且可忽略"）。
4. **数值不得冒充**：若该条的全部"证据"只有合成谱自检/拟合数值/图表 → 判 NEED_PROOF（这类结论往往 3–10 行符号推导就能补，正文却没有）。
5. 修复优先于降级：断言"按字面为假/过强"时，先判断其内核是否仍然正确、是否可挽救为精确命题。大多数"看似为假"的半解析声明（缺前提/缺修正项/把近似当恒等）内核都对 → 判 NEED_REPAIR，修改清单里给出修正后的命题原文（含修正项、前提、余项界），供 write 直接采纳；只有当该声明既补不出推导、又无法改写成站得住的精确命题（内核本身就是错的/纯经验拟合）→ 才判 NEED_DOWNGRADE，写明"为何无法修复"，给降级建议措辞（"命题 X"→"数值观测：在…数据上观察到…"）。**禁止默认把可修复的命题打成观测。**
6. 离散采样替连续对象（三支处理，防假闭环）：若命题证明依赖连续边界/集合、而代码只检有限采样点——判定顺序：(A) 修改清单要求给采样充分性解析界（C² 边界：弧偏差 $\varepsilon(h)\le\tfrac12\max|\gamma''|h^2$，一阶 $|\gamma'|h$；曲率上界全窗采样取 max 即数值常数；声明 $\varepsilon(h)+$判别裕度 $>0$ ⇒ 连续意义成立）→ 命题保留；(B) 给不出界则要求 rescope：把命题改述到代码真正验证的对象（"间距 $h$ 采样 + 弧偏差 $\le\varepsilon(h)$ 下…成立"），命题照留、声明域说清；(C) 两者皆不可 → 才降级为数值稠密核验，且降级不改名丢弃内容，须保留披露三量（网格间距 $h$、偏差 $\varepsilon$、判别裕度）。**禁止**"对连续对象下定理 + 有限采样验证 + 零误差分析"组合静默通过。

C 类（纯定义/直接代入即得/复述题面）不判，跳过，避免为琐碎断言制造推导。

### Step 3：独立复推（数学推理验证的论文级执行）

对每条 判定为"形式上像有推导" 的断言（防止"推导存在但推导是假的"——这正是假定理红线要防的），为每条派生一个子 Agent 做独立复核：不引用原推导，独立重推该结论，或主动找反例；能指出"第几步不成立 / 少前提 / 反例在此"才算发现问题。子 Agent 结论：
- `支持`：独立重推成立（在声明的任何等价/更强前提下都成立）→ 该条 OK。
- `反例/缺前提`：给出反例或指出缺口 → 若只是字面过强/前提不足而内核正确 → NEED_REPAIR（修改清单附修正命题原文）；若内核也错 → NEED_DOWNGRADE（附为何不可修复）。

派生规则：一次最多并行 3 条；每条给足上下文（引用原文公式与该小节路径）；子 Agent 只读 paper 源码。

### Step 4：聚合与写出报告

汇总每条处置 → 写出 `reports/MATH_PROOF_REPORT.md`：

```markdown
# 数学论证门禁报告

## 整题门禁裁决：APPROVED        ← 三值之一（文件末尾整行，供编排器锚定）：APPROVED / REVISE_HARD / REVISE_SOFT
## 门禁结论
（一句话：全部标签命题均带可复核推导与前提/余项；或列出 N 条缺陷 → REVISE）

## 扫描范围
（main.tex；小节清单；断言清单总数，标签类/强声称类/跳过类各多少）

## 断言清单
| # | 位置(文件:行) | 原句摘录 | 类型 | 推导? | 前提显式? | 余项界? | 独立复推 | 处置 |
|---|--------------|---------|------|-------|----------|--------|---------|------|

## 修改清单（仅当 REVISE_HARD/SOFT 时）
对每条 NEED_PROOF / NEED_REPAIR / NEED_DOWNGRADE 给出具体到小节的修改指令：
- NEED_PROOF：该补哪几行推导（要点式，如"对 R_A(Φ) 求导令 =0 → 与 R_2 同解；附 ∫cos2Φ sinΦ=0 及有限窗余项"）
- NEED_REPAIR：直接给出可逐字采纳的替换句/式（含修正项、前提、余项界）——write 必须逐字采纳，禁止意译（意译是此前引入"斜率写反"等新错误的根源）
- NEED_DOWNGRADE：降级后的建议措辞（原句 → 改写句），并写明"为何无法修复"
- 明确回 9Paper-writing 处理；本阶段不改 paper

## 未纳入项
（误报/跳过的 C 类及原因；无标签命题时的说明）
```

判词分级与输出：最终判词必须是文件末尾的 `## 整题门禁裁决：APPROVED` / `REVISE_HARD` / `REVISE_SOFT`（可再有空行），不要用"不追加…""无 REVISE"这类否定句当判词——编排器按这一行锚定。
- `APPROVED`：全部条目 OK（或无介入对象）。
- `REVISE_HARD`：清单含真错误（内部矛盾 / 假陈述 / 独立复推给出数值反例 / 斜率系数符号方向写反等硬伤）——不自动重试也不自动降级，直接转黄灯挂起等人工，**不得降级放行**。
- `REVISE_SOFT`：仅措辞级（字面过强 / 缺前提或余项 / 可披露的过强归因）——挂起后在面板上选「接受并披露」即可放行，并自动记入 `_KNOWN_WRITING_RESIDUALS.md`。
- 一条 HARD 顶掉全部 SOFT：清单里只要含任何真错误条目，判词必须为 `REVISE_HARD`；只有纯措辞条目才可判 `REVISE_SOFT`。REVISE 时**必须**给出修改清单，禁止只写"不合格"。

Web 裁决侧车（content-quality 启用时）：另写 `reports/MATH_PROOF_REPORT.verdict.json`（v2；本阶段必查 ID 由驱动注入：proof_validity/proof_applicability/optimality/narrative_consistency）。结构、category 路由与锚点要求见 `docs/CONTENT_QUALITY.md`「问题分类与机器裁决」——逐条列「前提→模型/代码实际证据→推导有效步骤→结论适用范围」；**抽象命题/未完成求解不得给最优性背书**；根源在模型/约束/随机过程 → 返修 `analysis`，纯文稿推导错 → `write`。 报告末尾裁决行与 JSON `status` 必须一致；程序校验不通过一律 UNVERIFIED，重试或披露不构成放行。

## 自检

- [ ] 每条处置都写了依据（在哪一行、缺什么），不是笼统"证明不规范"。
- [ ] 没有把"合成谱/数值/图表"当作证明放行过任何一条。
- [ ] 没有修改 `paper/` 下任何文件；没有发明/升级任何命题。
- [ ] 无标签命题的题：报告写 APPROVED 且注明"未发现需门禁介入的数学对象"，不强行造证明。
- [ ] 报告末尾有且仅有一条 `## 整题门禁裁决：…` 判词行（三值之一）。
- [ ] 清单含任何"内部矛盾/假陈述/反例/硬写反"条目时，判词为 REVISE_HARD（而不是 SOFT/降级放行）。
- [ ] 数值探测脚本写在 `_tmp/*.py`（保留，供下轮复用；项目根无遗留 scratch）。
