# 正文篇幅与公式排版协议

适用阶段：3analysis 初步组织论证；7Route-diagram 选择解释性几何图；9Paper-writing 分配篇幅；**14Layout-and-format 独占排版/版式/篇幅预算/编译**；15Verification 只读验收。此协议改善表达，不改变模型、数据或数学结论。

> 写作与终验时另读 `docs/WRITING_QUALITY.md` 的两节：
> **「图表引用：不许整句只指路」**（`…路线如图 1 所示。` 这种整句指路必须改写）
> 与 **「关键结论与数字要加粗」**（每个小问的结论数字要能一眼看到）。
> 这两条只在 `WRITING_QUALITY.md` 里写全（含判据与判例），此处只作入口，避免两处措辞漂移。

## 页数规则和写作计划

读取 config/publication.json。当前为论文模板口径，细节见 [国赛要求](CUMCM_2026_REQUIREMENTS.md)：

- **计页额度 = 摘要 + 正文**（赛区补充规定）：**合计上限 30 页**，
  摘要本身不超过 1 页。⇒ 一份「摘要 1 + 正文 30」的稿子是 31 页、超 1 页 ——
  正文要压到 29 才合规。**别只数「一～七」的页数就以为达标。**
- **摘要必须写满它那一页**：
  - **判据 = 版心填充率 ≥ 0.90**，`hard = 0.80`。机读键 `config/publication.json` 的
    `min_kind_fill.abstract`；量法在 `lib/publication/checks.py::kind_fills` —— 量出本文自己的
    版心（所有页非页脚块的最小 top ~ 最大 bottom），再看摘要页最低那个块到哪儿。
    **不靠字数估算**（同样字数，两行标题就少一行正文）。
    - `config/publication.json` 的 `min_kind_chars.abstract` 降级为兜底，只在量不出填充率时用。
  - 两档：填充 < 0.80 ⇒ 进 `issues`，`_mechanical_floor` 判死并回退到 ⑨ 论文撰写
    （据 `prose_issues` 标记改指 —— 摘要是文字，⑩ 无权改）；`[0.80, 0.90)` ⇒ 只出提示。
  - 同一条 `prose_issues` 标记还罩着「公式复核记录未绑定当前PDF」：那同样是阅读任务
    （逐条读公式、翻到物理页核对、再重签记录），只有 ⑨ 做得了；不标的话它会被判给 ⑩排版，
    而 ⑩ 既不能读公式语义也无权重签 ⇒ 下一轮报同一条 ⇒ 死循环。
    判据：`lib/publication/checks.py` 里 `formula_review_issues()` 的返回值也并进 `prose_issues`。
  - 对照尺（参考稿 `基于变物性耦合传热传质与动域模型的.pdf`）：
    其一页摘要 **92.7%**（1106 个非空白字符，字数口径约 1034 字）⇒ 差的是内容量，不是排版。
  - 按本模板版面 0.90 ≈ 整页 **1050 个非空白字符**。
  - 写满的办法是**加实质内容**（每问的方法要点、结论数字、检验与灵敏度各写足），
    不是放大字号、加行距、或重复段落。
  - 判据不是字数阈值：`min_kind_chars.abstract` 只是兜底。也不要把它做成 `warnings` ——
    本仓库没有一处读 warning（`_manual_checks` / `_mechanical_floor` 都只看 `issues`），
    写成 warning 就永远进不了 ⑨ 的返修单。规则层同理：`norms`「摘要写作要点」与 ⑨ 的 SKILL
    里若写「约 850–950 字内安全」，那是上限口径，与本节填充率判据冲突时以填充率为准。
- 「八、AI 工具使用说明」与「九、参考文献」**合计不超过 1 页**；附录单独起页、不限页；
  两者都不占上面那 30 页额度。不要目录、不要封面。计页口径只由 `config/publication.json` 决定。
- **写作目标是写满 30 页，宁多不少**。理由是超了可以压缩，少了是真少 ——
  篇幅不足没有补救手段，而论证缺口一旦被压缩掉就找不回来了。低于 25 页会出 warning。
- 但「写满」不等于灌水：不许用重复段落、把同一张图换个角度再放一次、
  拆句凑行来充页数。缺页数时补的是实质内容（建模过程、求解细节、结果分析、
  对照与检验、失败结果与局限），不是排版花活。

若 request 或题面明确给出不同口径，在开始写作时更新配置并注明依据，不通过改变口径迁就超页结果。

创建 reports/WRITING_PLAN.md：

- 列明排版引擎、模板、计页依据、上限和初稿目标。沿用已经确定的偏好；没有偏好时使用项目默认 LaTeX，不重复询问已确认事项。
- 按本题难度分配篇幅，列出章节、核心结论、必须保留的证据、预计页数。先列完整论证链，再估算能否落在上限内；参考页数允许调整，不给各问机械等分。
- 每张图和表注明正文、附录或不采用，以及其独有的解释作用。不采用的资产在图表清单 included=false 并说明原因；正文与附录实际采用的图都保持 included=true 并完成复核。
- 对每个子问题保留：变量/假设、模型、关键推导、求解说明、核心结果、关键验证、局限。具体数据和推导以当前结果与建模报告为依据。

## 超页修订顺序

实际计页未超过30时，不以达到参考页数为由删掉总路线图、必要推导、算法关键步骤或失败结果。每次压缩后检查“变量与前提→数学模型→求解过程→结果→验证与局限”是否仍完整，并在 WRITING_PLAN 给出各环节正文位置。**有剩余页数且存在论证缺口时优先补缺**，而不是继续缩图、缩格式 —— 这正是「宁多不少」的落地方式。反过来，缺页数时补的必须是实质内容，**不许用重复段落或排版花活凑满 30 页**。

图中文字不适合论文时执行 docs/WRITING_QUALITY.md 的路线图返修步骤，不将删除整图作为默认压缩方案。详细数表和重复诊断可迁附录；支撑主要结论所必需的证据保留正文。

先编译，再按实际页数处理，不能凭源文件长度猜页数：

1. 删除重复的题面复述、同义结论、求解流水账和重复公式。后问共享定义用明确交叉引用。
2. 将完整结果表、补充情景、详细参数、诊断图、重复代数步骤和完整伪代码移到附录。核心推导与决定结论可信度的验证保留在正文。**可迁的只有"补充"这一类**：题意示意图（几何/边界/坐标系/机制）、求解流程图、每问的关键结果图**必须留在正文**，超页也不许拿它们腾地方 —— 判据见 `skills/14Layout-and-format/SKILL.md` 的「哪些图必须在正文、哪些才进附录」。
3. 合并表达同一结论的相邻图，拆开缩小后难以阅读的密集图；调整浮动位置和明显多余的留白。
4. 编译、重新分类物理页面，检查每问论证链仍完整。不得通过缩字号、压页边距、把公式转图片、降低可读性或隐瞒失败结果来满足页数。

修改写入 reports/EDITORIAL_CHANGES.md：原位置、删/移/合并原因、新位置、正文保留的证据、交叉引用。不要为压篇幅重写模型或数值。必要内容仍超限时转黄灯等人工决策（延长 / 回退到 write 决定迁什么去附录 / 接受并披露），不提交超限版本，也不静默删核心内容。

## 物理页计数

页码从 PDF 第一张纸面算1，和印刷页码、目录重置页码无关。编译完成后逐页核对边界，准备 JSON，如下只是结构示例，数字必须替换为实际范围：

```json
{
  "schema_version": 1,
  "spans": [
    {"kind": "abstract", "first": 1, "last": 1, "title": "摘要"},
    {"kind": "body", "first": 2, "last": 25, "title": "正文"},
    {"kind": "references", "first": 26, "last": 26, "title": "参考文献"},
    {"kind": "appendix", "first": 27, "last": 32, "title": "支撑材料清单、完整代码与补充结果"}
  ]
}
```

一页同时出现计入和排除内容时按计入类别登记；封面和摘要共享一页时按 abstract。正文和附录明确分界，附录首节前换页便于核对，避免把正文页误报成附录。每页必须分类一次，无遗漏、无重复；不能仅将正文改名为附录以规避上限。

写作阶段从项目根运行：

```text
python -m lib.publication map <已核对的页面区段JSON>
python -m lib.publication report
```

map 把分类绑定到当前 paper/main.pdf 的 SHA256，并保存 paper/page-map.json。每次重新编译后核对并重新绑定，旧映射失效。report 写 reports/PUBLICATION_CHECK.json；缺 PDF、缺映射、版本不符、分类遗漏、超页都不能通过。

终验只读运行 `python -m lib.publication check`。该命令独立读取当前 PDF，不信任旧报告中的页数；15Verification 仍须核对每个区段的标题和正文/附录真实边界。映射是写作者声明，哈希只能绑定版本，不能证明分类诚实。公式排版启发式告警是复查线索，不是数学错误裁决。

## 数学公式的组织

- 一块公式表达一个层次：定义、目标函数、联合约束、推导、数值代入分开安排。
- 联合约束按关系符对齐；分段函数用 cases；长推导用 gather（每行一条，末行以外的行用 `\notag\\[-12pt]`），在关系符处换行；**不要 equation 套 aligned**（净空 −8.4pt，会压到下一行正文；配方见 docs/WRITING_QUALITY.md）。
- 同一推导不逐行机械编号；重要且需要引用的公式编号，其余可不编号。遵守模板编号，是否按节编号由模板决定。
- 说明性下标用正体，变量保持数学字体；单位与数值间适当留白；算子用规范命令。向量、集合、矩阵符号全篇一致。
- 首次定义后解释符号、单位和适用条件，不重复打印整套模型来凑“模型汇总”。模型汇总确有价值时展示新增关系或简洁索引。
- 外观优化前后逐项核对量词、上下界、不等号、上下标和求和/积分范围。排版不能改变数学语义。

### LaTeX

将 lib/publication/templates/math-style.tex 复制到 paper/math-style.tex，并在导言区 `\input{math-style.tex}`。实际模板已自带此文件时沿用；自定义宏若重名先协调，不重复定义。参考 math-example.tex 的独立资源分配/向量恒等式示例。字体遵守比赛模板，保持公式文字大小，不用 resizebox/scalebox 缩公式。

## 验收责任

两个 PDF：正文工程 `paper/` 编成 `正文.pdf`（末页是「支撑材料文件清单」表），附录工程
`paper_appendix/` 编成 `附录A.pdf`（补充推导/图表，不限页）。页数口径只管正文；
附录只查 A4 尺寸与 20MB 上限。两个 PDF 的公式编号要接续（附录 `main.tex` 里
`\setcounter{equation}{N}`，N = 正文公式总数，编译后量出）。**源码不排进论文** —— 以散装 `.py` 提交，
在清单表里逐项登记；清单同时是打包依据（`delivery`），两边必须逐项一致。

**14Layout-and-format** 完成编译、页数检查与逐页视觉验收（图表审阅、迁移记录、公式告警处理也归它，因为它独占排版层）。15Verification 只审查，逐页检查长公式、编号碰撞、图注和小字号，结合数学论证门禁检查内容。Web verify 再执行确定性页数检查，超限或无法核实时 返修 format（verify 的默认回退目标是 format）。自动检查不会替代科学判断和最终 PDF 目检。
