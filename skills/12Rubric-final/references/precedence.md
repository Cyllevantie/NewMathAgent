四份评分标是别人写给通用场景的，其中相当一部分建议与本项目的现行口径冲突。
本文件是它们的唯一仲裁依据。**读任何一份 `rubric_*.md` 之前先读这里。

## 优先级（冲突时从上往下）

1. 用户当次明示的要求
2. 仓库 `config/` + `docs/` + `templates/` 的现行口径
3. 评分标原文**

按第 1、2 级执行、压掉评分标原文的每一条，都要在 `RUBRIC_REVIEW.md` 的
「已改口径（precedence_override）」一节里记一行 —— 否则下游看到判词的人会以为
评分标没被读过。

## 关于 HTML/PDF 报告形态（R6）的说明

四份评分标都花了大量篇幅规定报告的视觉样式（配色十六进制值、字号 px、卡片阴影…）。
本项目一律不采纳**，理由有二：

1. 本链的产物是 `reports/*.md`，由 Web 面板与人工阅读；引入 HTML 报告会多出一份
   与 `.verdict.json` 平行的、需要单独校验一致性的产物。
2. 样式规范占了那几份提示词约三成篇幅，照抄会把真正可判的检查点淹掉。

要做的是把它们规定的那几列抓住：「核查结果 / 问题位置 / 问题简述 / 整改建议」——
这四列已经落在 `RUBRIC_REVIEW.md` 的判词清单里。

## 关于「致命问题一票否决」

三份评分标的致命项定义互相吻合，直接采纳：

- 摘要严重不合格（<600 字 / 超一页 / 无具体数值 / 结构混乱）
- 模型整体创新性极低或完全无创新（直接套用现成模型且无任何改进）
- 排版混乱、图表粗糙、字体字号不统一
- 全文无任何模型检验（无灵敏度 / 误差 / 稳健性分析）

其中第 2、4 条的判定权在本阶段；第 1、3 条先看 `14Layout-and-format` / `15Verification` 的报告，
不要重复判。存在任一条 → 获奖预测直接写「可能未获奖」，不得预测任何等级奖项。

## 本项目额外要求 ⑫ 一并判的两条

这两条不在那四份评分标里（它们只管"假设 3–5 条""关键词 3–5 个"这类个数问题），
是本项目自己的口径；细则见 `math_modeling_norms.md`「摘要写作要点 / 假设节编制纪律」
与 `skills/9Paper-writing/SKILL.md`。⑫ 请把它们与评分标条目同等对待 ——
发现问题按 `must` 写进判词清单（位置 + 现状 + 该怎么改），让 ⑬ 就地改或回退 ⑨；
**不要**只写进"参考建议"（那样没人会去改）。

### K1 关键词必须是"本题特有"

- 判据：每个关键词都要指得出题面对象 / 本文的模型特征 / 本文真用的关键方法。
  「灵敏度分析」「数值模拟」「优化分析」「数学建模」这类任何论文都能写的通用词，
  一律算不合格。
- 个数仍按仓库口径：4–6 个、单独一行、末行别只剩一两个字。
- 参照件样例（每个都落回题目）：热风烘干；变物性耦合传热传质；柱坐标有限体积；
  材料坐标下的动边界；阈值求根。
- 优选具体短语而不是单词：`动域与材料坐标` 强于 `材料坐标`，`阈值求根` 强于 `事件定位`。

### K2 模型假设每条 1.5–2 行（约 55–80 字）

- 判据：从交付 PDF 上数行数（不是按字数估 —— 按字数估会低估半行）。
- 写法：一句话说清"假设什么" + 一句话说清"为什么可以这么假设"；展开的量化影响
  （"放宽后位移约 3 h""放宽为阶梯读数后增加 0.14 h"）应挪到正文对应处或附录。
- 标尺：6 条全是 3 行 ⇒ 判不合格；参考件同位置多数 2 行、个别 3 行。
