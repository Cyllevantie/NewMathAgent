# 按评分判词定点返修

> 通用执行纪律（增量返修 / 缩比预估 / 分段落盘 / 方法标记 / 返修只动清单内）见 `../_references/stage_discipline.md`。
> 本阶段适用：一（增量返修，含 1.1 探针复用）、五（返修只动清单内）。
> 探针/量测脚本要复用（通用纪律 一·1.1）：本轮写的取证/量测脚本一律留在 `_tmp/`
> （另有散落的在 `tmp/`，两个都要看）；下一轮开工第一步 = `ls _tmp/ tmp/` → 把上一轮
> 为同一批对象写过的脚本先原样重跑（秒级，确认数在当前版本里还成立）→ 只对本轮新出现或改过
> 的对象写新脚本。别每轮从零重写 —— 全链 776 个自写脚本里 **683 个（88%）只被用过一次**
> 就再也没人碰。复用探针 ≠ 跳过复核：探针只是取证手段，判定仍逐条对着当前版本做。
> 豁免：二（缩比预估）、三（分段落盘）、四（方法标记）—— 本阶段只改文稿，不跑长计算。

本阶段位于 12Rubric-final 之后，是「找漏洞 → 改漏洞」里的「改」。
它的输入是 `reports/RUBRIC_REVIEW.md` 与 `reports/RUBRIC_REVIEW.verdict.json` 里的判词清单。

> 没事时不会跑你：`12Rubric-final` 明确通过（只剩轻微项）时，驱动会跳过本阶段 ——
> 没有判词可处置，白调一次 agent 不值当。真的想强制跑，从 `12Rubric-final` 重跑
> （它会重新判词，判出东西来本阶段自然就跑了）。

## 它不是 `write` 的替代品

`write` 在别处的回退边（`10Math-proof-gate→write`、`11Cross-question-check→write`）一字未动。
本阶段只服务 `12Rubric-final` 一家。这决定了下面的边界是硬的。

## 边界：只能改论文侧

| 归本阶段（改文稿即可） | 不归本阶段（改了就是洗白） |
|---|---|
| 措辞、句式、段落结构 | 模型选错 / 假设不合理 → `3analysis` |
| 摘要、结论的表述（不改变其数值口径） | 数值、指标、口径错了 → `5coding` |
| 创新点的表达（把已有的创新讲清楚） | 创新点本身不存在（模型确实没改进）→ `3analysis` |
| 可解释性叙述、优缺点表述 | 检验没做 → `6Robustness` |
| 图文编辑、图注、图表标题 | 图画错了 → `7Route-diagram` |
| 引用位置与格式 | 版式（浮体/超页/编译）→ `14Layout-and-format` |

判据：动手前问「这只是换一种说法，还是换了事实？」若是换了事实 —— 停手，
在报告里写成「不属本阶段能改」，让驱动把它退回对应阶段。

> 反例（这个阶段最容易犯的错）：判词说「缺少对比实验」，于是把正文里一段描述改写成
> 「本文与 XX 方法做了对比」—— 而根本没跑过那个对比。**这是伪造证据，绝对禁止**。

## 硬规则一：改之前先复核每条判词是不是真的

逐条对照当前盘面重新取证。三条出路：

| 复核结果 | `disposition` | 动作 |
|---|---|---|
| 属实 | `fixed` | 按判词定点改；改完附 `grep` / `diff` 的真实输出 |
| 不属实（论文里本来就有、换个名字、在附录/表里、在 `ROBUSTNESS_REPORT.md` 里） | `not_reproduced` | 一个字都不改；附证据原文 |
| 属实但代价过大（判词属 `optional`） | `deferred` | 不改；附成本估计 |
| 属模型/数值/实现类（本阶段根本改不了） | `out_of_scope` | 不改；写明该退到哪个阶段 |

四条都要落进 `reports/FIX_REPORT.json` 的 `items`，驱动会逐条对账（见「必须产出」）。

`not_reproduced` 这一栏是防「照着判词改坏本来对的东西」的机械手段 ——
与 `stage_discipline.md` 第五节「改前留副本、改后 diff、清单外一律回退」同源。
它和"改好了"一样是合格的产出，不要为了显得有产出而硬改。

## 硬规则二：评分标建议加的主观第一人称，一律写成「本文」

评分标（尤其是 AI 痕迹那份）的「人味表达库」建议加入「我们提出…」「我们认为…」
「我们倾向于…」这类主观第一人称。本项目不用第一人称：

- 判词要求加主观表述时，写成「本文提出…」「本文认为…」「本文倾向于…」。
- 既有的「我们」若被判词点名，同样改写成「本文」，语义不变。
- 口语化表达（「说白了」「换个角度看」「有意思的是」）与设问句**一律不采纳** ——
  那是该评分标里不适用的一节，详见 `../12Rubric-final/references/precedence.md` 的 R2。

这一条不做全文禁词扫描：只在按判词改写时遵守，不加到 `15Verification` 的文本门禁里。

## 执行方式

1. 读 `reports/RUBRIC_REVIEW.md` 的判词清单，按 tier 从高到低处理（`fatal` → `must`；
   `optional` 默认不动）。
2. 只处理 `claim` 类判词（论文侧）。清单里若混着模型类判词，说明驱动本该回退而不是
   调起本阶段 —— 停手，在报告里写明并把 `target` 交回。
3. 逐条复核 → 属实才改。修的时候要确认 12 说的是真的再修，**别把正确的改错了** —— 判词说的位置/数字，先自己到
   `paper/` 与 `results/` 里核一遍：复核不属实（或已被别处修过）就在处置表里记
   `not_reproduced` + 依据，一个字都不改；只有核实属实才动笔。宁可少改一条，
   不可凭判词转述去改一条本来是对的。
4. 改前留副本：`cp paper/sections/X.tex tmp/X.tex.before`；改完 `diff` 出全部改动行，
   逐行确认每一处都对应判词清单里的某一条；清单外的改动一律回退。
5. 改完重编译（`xelatex` 跑两遍）确认没改坏版式；改了正文/图注/表格的还要核页数。
   页数的核法有坑：`publication check` 比的是"页面映射绑定的 PDF
   sha"，你刚重编译过 ⇒ 它会报「页面映射未绑定当前PDF」而不是页数。正确顺序是：
   `xelatex ×2` → `python -m lib.publication map <spec>`（按当前 PDF 重绑，物理页范围没变就照抄
   `paper/page-map.json` 的 spans）→ `python -m lib.publication check`，这时才看得到真实页数。
6. 三条硬约束：
   - **版式必须与既有内容一致**：你只改文字，不许引入新的字号/行距/缩进/字体；改完把改动段落
     与同节未改动段落逐项对照（字号、行距、首行缩进、公式上下文间距）确认同款。
   - **总页数不许涨**（模板给的 30 页上限）；附录与"八/九"那页的规则也别碰。
   - **一旦涨了必须压内容**，而且优先从「5 模型的建立与求解」里选一部分压缩：
     先压重复表述、过程性叙述与可由图表替代的文字，**不许删结论、判据、关键数值与检验证据**；
     压完重编译再核页数，直到不涨为止。别用缩字号/调行距/缩页边距去凑 —— 那是版式，属 14。
7. 写 `reports/FIX_REPORT.md`。

> 版式细节（行距、浮体位置、字号）不归本阶段 —— 改动若让版式出问题，写进报告的
> 「需 14Layout-and-format 复看」一栏，不要自己动手调 preamble。

## 必须产出

### ① `reports/FIX_REPORT.json`（机器校验，缺了会被驱动打回）

驱动会读它并逐条对账：每条 `must`/`fatal` 判词都必须在这里出现一次，且必须带证据。
写不出来的话本阶段不算完成。

```json
{
  "schema_version": 1,
  "stage": "fix",
  "items": [
    {"id": "R-3",  "disposition": "fixed",
     "evidence": "paper/sections/5_problem2.tex:88 —— 原「在此基础上，本文进一步分析了…」已按判词改写",
     "recheck": "grep -c \"在此基础上\" paper/sections/*.tex → 0；xelatex 两遍通过"},
    {"id": "R-7",  "disposition": "not_reproduced",
     "evidence": "判词称「全文无灵敏度分析」，实际 paper/sections/6_check.tex:12 有 6.2 灵敏度分析整节，"
                 "含 3 组参数扰动表与 1 张可视化",
     "recheck": ""},
    {"id": "R-11", "disposition": "deferred",
     "evidence": "判词为 optional：建议补一组与 XX 方法的对比实验。估计需 code 跑 40–60 min + 重出 2 张图 + 改摘要与结论各一句",
     "recheck": ""}
  ]
}
```

`disposition` 只能取这四个值：

| 值 | 含义 | 要求 |
|---|---|---|
| `fixed` | 属实，已按判词定点改 | `evidence` 指认改动位置；`recheck` 写复验方式与真实输出 |
| `not_reproduced` | 不属实，一个字都没改 | `evidence` 必须引用论文里本来就有那段（文件:行 + 原文） |
| `deferred` | 属实但代价过大（判词属 `optional`） | `evidence` 写成本估计 |
| `out_of_scope` | 属模型/数值/实现类，本阶段改不了 | `evidence` 写明该退到哪个阶段、为什么改不了 |

`not_reproduced` 和 `fixed` 一样是合格的产出 —— 不要为了显得有产出而硬改。
反过来，一份"啥也没做也没说为什么"的报告会被驱动判为不合规并打回。

### ② `reports/FIX_REPORT.md`（人读）

```markdown
# 按评分判词返修报告

## 整题结论：DONE / PARTIAL
## 逐条处置
（与 `FIX_REPORT.json` 的 items 一一对应；JSON 是驱动对账用的，本表是给人读的）
| # | 判词 tier | 位置 | disposition | 动作 | 复验输出 |
## not_reproduced（判词不属实，未改稿）
（每条附证据：判词说 X，实际在 <文件:行> 有 <原文>）
## deferred（属 optional，未改稿）
（每条附成本估计）
## 不属本阶段的判词
（模型/数值/实现类；写明该退到哪个阶段、为什么本阶段改不了）
## 改动范围自查
（`diff` 的行数；清单外改动 = 0 的确认；重编译结果）
```

**必须真的跑完第 4、5 步并把真实输出贴进报告** —— 自查行必须来自命令输出，不是来自意图。
