# 大流程图规范：问题路由树 / X 问泳道

> 适用：`fig_roadmap`（论文图 1「分析流程图」）。它说明建模、方法、操作与判断，
> 不是代码 I/O，也不是把正文一句话画成三格直串。
> **停用**：时间轴版式；`roadmap-5band` / `roadmap-3phase` / `framework-3col` /
> `stageflow-3col` / `taskflow-land` 五个线性模板。

## 0. 字体 / 语言 / 宽度：跟论文其他图完全一致

`fig_roadmap` 不是独立画风。开工先跑：

```bash
python skills/figure-studio/scripts/resolve_context.py --write
```

按它解析出的 `language` / `font` / `width_mm` 画：中文论文 → 微软雅黑、中文标签、160 mm；
英文论文 → Arial、英文、183 mm。字号与数据图同一套（正文 ≥9 pt，最小 8 pt）。
**图内不混用中英文**（变量、单位、专有名词除外）；不要沿用旧模板的 16 px 大字号或 954 px 画布，
也不要因为换了结构就单独换字体。`fig_roadmap` 与数据图、其他示意图放在一起时，字体/字号/语言必须看不出差别。

**按最终印刷宽度定画布，不要按屏幕稿缩**：中文 160 mm ≈ 605 px（96 dpi），路线图占
0.85–1.0 栏宽时画布 515–605 px；节点正文 12–14 px（≈9–10.5 pt），标题 15–17 px。
不要画 1500 px 的屏幕稿再塞进 160 mm —— 10 px 字会缩成约 3 pt；
也不要沿用 954 px 竖版 + 16 px 字再整体缩到 0.85 栏宽（≈6.5 pt）。

## 1. 先定结构，再动笔

从 `reports/ANALYSIS_MODELING_REPORT.md`、`reports/RESULTS_REPORT.md`、`reports/FIGURE_PLAN.md`
和题面里列出四类东西：

- 输入：题面给的数据、序列、几何、初值；
- 共用骨架：模型方程、边界、离散、线性求解；
- **真实条件**：时间窗、物性是否随 C/T 变、是否收缩、是否复用前一问的解；
- 各问各自的方法与关键结果，以及检验。

然后二选一：

| 条件 | 结构 |
|---|---|
| 存在至少一个真实条件，能把各问路由开 | **问题路由树**（首选） |
| 各问是并列切片，没有真实路由条件 | **X 问泳道**（备选） |

没有第三种。不要退回五带/三阶段/三栏/横版流水线；不要画时间轴。

## 2. 问题路由树（首选）

拓扑（自上而下，或自左向右）：

```
开始（对准输入组中心）
  → 输入组（4 个平行四边形，母线汇入）
  → 共用模型容器（容器内 4–6 个小框：守恒基准 / 控制方程 / 边界 / 离散 / 物性 / 事件）
  → 条件菱形链（每个菱形只问一个真实二选一）
       ├─ 是/预热 → Q1 支链（3–5 个处理小框 + 1 个结果文档）→ 结束
       ├─ 否/全过程 → Q2 支链（含两项校核）→ 结束
       ├─ 是/加收缩 → Q4 支链（坐标变换、收缩求解、效应分解）→ 结束
       └─ 是/复用 Q2 解 → Q3 支链（判据、扫描 + Brent、首达/稳定）→ 结束
```

规则：

- 每个菱形出口必须有真实标签（「是 · 预热段」「否 · 全过程」「是 · 加收缩」）；
  没有真实二选一就不画菱形，改画处理框。
- 每条支链是一列**独立小框**，一个框只放一个事实；不要把「方法 + 判据 + 结果」塞进一个大框。
- 支链末端用文档形放关键结果；每条支链各自有结束胶囊，对准末框中心。
- 共用模型容器是**容器**，里面的每个要素要有自己的小框；容器本身不加正文。
- 输入组、模型容器、支链列之间用母线/短正交线连接，不画 N 条斜线。
- 图宽按 §0 定（中文 160 mm 折 515–605 px；英文 183 mm 同理折算），本节不另设画布宽度；
  支链多时按列排开，列间距 20–35 px（约 1.5–2.5 倍正文字号）。

## 3. X 问泳道（备选）

拓扑（上→下）：

```
开始（对准第一条输入中心）
  → 输入组（4 个平行四边形）→ 共享模型链（5–6 个小框，横向母线）
  → X 条纵向泳道（X = 题目问数；每问一条，互不穿插）
       每条：问号 + 问名（着色标题条）
             → 窗口/输入（平行四边形）
             → 2–4 个方法小框
             → 1 个真实判据菱形（是/否）
             → 结果文档
  → 底部检验母线（5 个小框）→ 结束（对准检验组中心）
```

规则：

- 四条泳道用同一套纵向节奏（同层同高），读者可以横向比较。
- 每问的判据必须真实（`t = 1800 s?`、`t = 72 h?`、`max_r C ≤ 0.15?`、`t = 50.83 h?`），
  出口标「是/否」；「否」回到本泳道的上游框，不跨泳道。
- 泳道之间不画交叉箭头；Q3 复用 Q2 解用「输入：复用 Q2 解」的平行四边形表达。
- 顶部输入/模型与底部检验各用一条母线统一进出，不要每问各画一条长箭头。
- 图宽同 §0（中文 515–605 px）；四条泳道等宽，间距 8–15 px。

## 4. 形状与颜色（语义固定，色值从 config 取）

本节只定形状与语义；具体色值一律从 `config/visualization.json` 的语义键取，不在文档里写死。

| 语义 | 形状 | 填充 / 边框（语义键） |
|---|---|---|
| 输入 / 数据 | 平行四边形 | `grid` 浅底 / `line` 边 |
| 处理 / 方法 | 圆角矩形（rx 8–10） | `grid` 浅底 / `palette[0]` 边 |
| 判断 | 菱形 | `grid` 浅底 / `warn` 边（仅阈值/异常/警示；普通二选一用 `line`） |
| 输出 / 结论 | 文档形（下沿波浪） | `box` 浅底 / `line` 边，文字 `ink` |
| 检验 | 圆角矩形 | `grid` 浅底 / `line` 边 |
| 开始 / 结束 | 胶囊 | `box` 浅底 / `line` 边 |

文字用 `ink`；不要把颜色当装饰。`warn` 只用于阈值/异常/警示，不拿它给普通分支上色。

## 5. 硬规则（违反任何一条都不算完成）

1. 图内不出现解释性旁白、图例、注、脚注、总结条；只留节点事实与分支标签。
2. 一个框里出现并列项，就拆成多个小框；大框只做容器。
3. 文字先量后画：框内文字水平、垂直都居中；放不下就加宽/换行/缩字号，绝不溢出。
4. 开始/结束胶囊对准首/末框中心；箭头垂直进入/离开。
5. 菱形只用于真实分支；出口标「是/否」或真实工况；不造伪判断。
6. 箭头从框边到框边；不悬空、不穿框、不绕圈、不在框内拐弯。
7. 同层同宽、同行同高、间距统一；不留大片空白。
8. 字号 ≥ 9 pt；节点文字 ≤ 2 行；长解释留在正文。
9. 一张图只讲一条阅读路径；支链/泳道是并列，不是第二套主线。
10. `fig_roadmap` 可以密（20–35 个框），但每个框只承担一个事实。

## 6. 生成后的强制自检回路

渲染 PNG 后逐框看，发现问题改脚本/XML 再渲染，直到下面 8 条全过；
每轮把「第几轮、改了哪些框、复验结果」写进 `reports/DRAWIO_REPORT.md`。

1. 框内文字块的水平中心与框中心偏差 ≤ 4 px（或 ≤5% 框宽）；垂直同理。
2. 文字不越框线，左右留白 ≥ 4 px；字号 ≥ 9 pt。
3. 起止胶囊对准首/末框中心。
4. 菱形都有真实出口标签，没有伪判断。
5. 箭头不悬空、不穿框、不绕圈。
6. 没有解释性文字、图例、注、总结条。
7. 并列项都拆成了小框。
8. 行列对齐、间距一致、没有大片空白。

`../paper-diagram/scripts/check_layout.py` 只能查溢出/重叠/穿盒，**不查文字居中**；
第 1 条必须靠打开 PNG 量框与文字包围盒。

如果走 SVG / 自绘而不是 draw.io：`text-anchor` 只认 `start` / `middle` / `end`。
把 `center` 写进去会被浏览器与 PyMuPDF 当成 `start`，表现是「文字从框中心起排、右半边溢出」——
2026A 的 D03 就栽在这上面，代码里写的是 `anchor="middle"`，底层却传成了 `center`。
**判据只能是渲染后量包围盒，不能只看代码里写了 middle。**
