# ⓪ 题目读取（读题）

> 通用执行纪律见 `../_references/stage_discipline.md`。本阶段适用：一（先看盘上有什么，别急着重写）、
> 六（分段落盘）。不适用"返修只动清单内"那几条 —— 它不返修任何东西，只读。

本阶段是整条链的第一步，也是唯一一步不产出论文/代码的阶段：它把上传进来的整个文件夹
（题面 PDF/图片、Excel 模板、数据表、说明文档……）读一遍，把"题目到底在问什么、每份文件是什么、
数据长什么样、哪里有疑问"讲清楚，交给人核对。人点确认之后，链才从 ① 文献定向 起跑。

## 两条硬边界（违反会当场挂起整条链）

1. 只读：**绝对不要**往 `request/` 或 `data/` 里写、改、删、移动任何文件。
   驱动在每个阶段执行前后各取一次输入指纹（`lib/web/server.py` 里 `_source_digest()` 的比对，
   见 `run_stage` 的"审核/执行期间输入发生变更"那条），而那个指纹就是 `request/` + `data/`
   的内容哈希 —— 你一改，本阶段立刻被判 `unverified`、整链挂起，而且提示文案会把方向指错。
   想改材料结构就写进报告里让人改：确认页上有逐份文件的"去向"下拉，由驱动在链外搬。
   你的产物只写 `reports/`（下面那两份）。
2. 不编：报告里出现的每一条事实（题面原文、文件名、表头、数据范围）都必须在材料里读得到。
   引用题面要逐字。看不出来就写进 `uncertain`，**不许猜**——下游 ② 建模设计 会拿你的结论去理解题意，
   猜错一条比少写十条贵。

## 产出（两份，缺一不可）

| 文件 | 给谁看 | 要点 |
|---|---|---|
| `reports/INTAKE_REPORT.md` | 人（确认页 + 侧栏 + 提交件） | 题面逐字转写、子问题清单、每份附件是什么/怎么用、数据结构与口径、明确列出不确定处 |
| `reports/INTAKE.json` | 驱动与确认页（机读） | 下面这份 schema；确认页的"去向"表就是照它画的 |

```json
{
  "schema_version": 1,
  "problem": {
    "file": "request/_inbox/题目.pdf",
    "text": "……你认为的题面全文（可复制文字；扫描件就照图逐字敲）……",
    "chars": 3120, "pages": 3,
    "subquestions": ["问题一：……", "问题二：……"],
    "confidence": "high|medium|low",
    "uncertain": ["第 4 页那张表格里的单位看不清"]
  },
  "files": [
    {"path": "request/_inbox/附件3/result1.xlsx", "role": "attachment",
     "target": "request/attachments/附件3/result1.xlsx",
     "why": "文件名含『附件3』，与题面『结果填入附件3的模板』对应"}
  ],
  "notes": ["附件1 的列名没有单位"]
}
```

`role` 只能取这五个（确认页的下拉就是它们，写别的会被拒）：

| role | 含义 | 落点 |
|---|---|---|
| `problem` | 题面本身（全包只能有一份） | 会另存一份 `request/problem.<ext>` |
| `attachment` | 附件（模板、图、说明文档…） | 默认 `request/attachments/<原相对路径>` |
| `data` | 明显是数据集、且本来也当不了题意锚点的大文件（.mat/.npz/.zip/几百 MB 的表） | `data/<原相对路径>` |
| `ignore` | 与本题目无关（别人的旧文件、系统垃圾） | 不动 |
| `needs_manual` | 你处理不了的（`.zip`/`.rar` 压缩包、`.docx` 之类） | 不动，并在报告里说清"该怎么处理" |

默认全给 `attachment`，别随手判 `data`：只有落在 `request/` 里的文件才能当题意锚点
（`lib/web/content_quality.py` 硬判后续阶段的 `source.file` 必须在 `request/` 下），放 `data/` 就
等于放弃了"这条要求在题面里有原文"的可核查性。

## 怎么读

1. 先看盘上有什么：材料在 `request/_inbox/`（原始结构，含子目录）与 `data/`。用
   `Get-ChildItem -Recurse` 列全，别只看顶层 —— 模板经常在子目录里（如 `附件3/result1.xlsx`）。
2. 逐份读：PDF 用 `python -c "import fitz; ..."` 抽文本（扫描件没有文字层，要照着图看）；
   Excel 用 `openpyxl` 读表头与前几行（别整表读进上下文）；图片直接看。
3. 看清"哪份是题面"：题面可能不在顶层（上传时常连外面那层文件夹一起传，如
   `赛题包/题目.pdf`），也可能不止一份（正题 + 附录 + 勘误）。以内容判断，不靠文件名猜；
   拿不准就在 `needs_manual` 里说明，别硬选。
4. 落盘：先写骨架（`INTAKE_REPORT.md` 与 `INTAKE.json` 各一份最小可读版本），再逐项回填 ——
   本阶段后面就停着等人，写到一半跑没气会让人看到一份空报告。
5. 写完就停。驱动会在你结束后亮黄灯等人核对；**不要**自己去改材料、也不要往下做建模。

## 报告里必须有的四样

1. 题目问什么：逐问转写 + 每问要交什么（数值？方案？表？）。
2. 材料清单：每份文件 → 是什么、哪一问要用、里面大概长什么样（表头/行列数/单位）。
3. 口径与坑：单位、时间基期、量词（"每种"还是"总共"）、精度要求、题面里相互矛盾的地方。
4. 不确定处：看不清/读不懂/需要人拍板的，逐条列 —— 这是这个阶段最有价值的产出，
   因为后面每一步都建在"题读对了"这个假设上。
