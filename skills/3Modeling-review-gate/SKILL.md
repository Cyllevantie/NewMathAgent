# 建模评审与机理校验（门禁）

> 评审对照清单见 `../_references/math_modeling_norms.md` 末尾「建模决策评审 A / 机理选择评审 B / 数据严谨性预检 C」三节；本 SKILL 的三查即对应 A/B/C。
> 通用执行纪律（增量返修 / 缩比预估 / 分段落盘 / 方法标记 / 返修只动清单内）见 `../_references/stage_discipline.md`。
> 本阶段适用：一（增量返修，含 1.1 探针复用）、六·6.1（先落骨架再深挖）。
> 探针/量测脚本要复用（通用纪律 一·1.1）：本轮写的取证/量测脚本一律留在 `_tmp/`
> （另有散落的在 `tmp/`，两个都要看）；下一轮开工第一步 = `ls _tmp/ tmp/` → 把上一轮
> 为同一批对象写过的脚本先原样重跑（秒级，确认数在当前版本里还成立）→ 只对本轮新出现或改过
> 的对象写新脚本。别每轮从零重写 —— 全链 776 个自写脚本里 **683 个（88%）只被用过一次**
> 就再也没人碰。复用探针 ≠ 跳过复核：探针只是取证手段，判定仍逐条对着当前版本做。


本阶段是完整工作流的第 4 步，位于建模设计（2Modeling-design）之后、代码实现（4Coding-and-computation）之前。它是这套融合 agent 区别于普通建模助手的关键门禁：在建模方案"写死成代码"之前，先由独立视角把住三道关——数学、题意、机理。

**为什么必须有这一关（背景）**：纯自动建模工具常见的失败不是"公式算错"，而是"在错误的目标/约束下算出数学上自洽但违背题意或机理的解"。典型症状：

- 题目要求"分组并给每组的检测时点"，模型却因目标函数权重失衡给出"K=1 不分组、全体一个时点"的退化解（把 12 周后的惩罚设得过陡、把"过早检测失败"惩罚设得过软，优化器便全体缩到 12 周）。
- 医学题要求以"常染色体三体"为判定对象，纯数据驱动模型却把某个衍生/辅助量（如 X 染色体浓度）捧成最强预测因子，把机理主变量（常染色体 Z 值）挤成"不显著"，被领域专家判定为机理倒错。

本门禁的三查正是为了拦截这两类错误。它读取 1Literature-orientation 的机理基线与 3analysis 的建模报告，做独立判定。

## 适用性守则（防"把示例当硬性要求"——重要）

上面的背景例子（K=1 时点、Z 值/c_X）只用于说明"这类失败长什么样"，不是对每道题的硬性要求。评审与建模都必须按本题决定适用性：

- "保障率/覆盖率约束"只在题面隐含"对某群体/批次的保证"时才应要求（如要求某比例个体达标/满足某指标、或方案须保证不漏某类人）。若本题无此隐含，**不得**以"没加 ≥95% 约束"为由判 FAIL——那会误伤其它题型。
- "以某机理变量为主"的判断必须来自本题的 LITERATURE_DIRECTION 与题面机理，**绝不套用其它题的主变量**（不存在"某类题就该用某变量"的固定答案）。
- 评审第一步：判定每个子问题属于哪种题型（优化 / 预测 / 评价 / 机理 / 图论网络 / 统计判别 / …），先按 `../_references/math_modeling_norms.md` 对应题型的"防错速查"小节逐项核对，再叠加本 SKILL 的通用纪律 A/B/C。
- 这些通用纪律是：优化核对目标与约束的题面依据；边界解或单组解需检查原因与敏感性，合理时保留；判别的主变量要合机理、测量噪声要按领域惯例去偏；数据要分清单位、分层防泄漏、小样本降级。

## 输入

1. `reports/ANALYSIS_MODELING_REPORT.md`（3analysis 产出，含每问决策变量/目标函数/约束/求解算法/代码契约）。
2. `reports/LITERATURE_DIRECTION.md`（2literature 产出，机理基线 + 推荐方向）。

## 必须产出

在当前工作目录的 `reports/` 下创建/更新 `MODELING_REVIEW_REPORT.md`：

- 逐子问题的评审结论（每问给 PASS / FAIL / PASS_WITH_REVISION）
- 每条结论附证据与具体修改清单（明确到"目标函数第几项应改成什么""应加哪条约束""哪个特征不该作主变量、应改用什么"）
- 末尾给整题总体结论：APPROVED（放行进代码）/ REVISE（退回建模手）
- 收尾必写（防 no_report 白跑）：全部结论确定后，**最后一动必须是 Write/更新 `reports/MODELING_REVIEW_REPORT.md`**，写完即结束；不要"想好结论就停"。若这是 no_report 重试轮（上一轮已做主体分析只是没落报告），**直接续着汇总写报告，不要重做审查**。落盘后可自查 `test -s reports/MODELING_REVIEW_REPORT.md`。

Web 裁决侧车（content-quality 启用时）：另写 `reports/MODELING_REVIEW_REPORT.verdict.json`（v2；本阶段必查 ID 由驱动注入：task_fidelity/quantifiers/stochastic_semantics/model_assumptions）。结构、category 路由与锚点要求见 `docs/CONTENT_QUALITY.md`「问题分类与机器裁决」——**题意/约束/随机过程/实现缺陷即使标 soft 也回 analysis/code，不得写成措辞问题**；必须独立对照 request/problem.md 原文复核量词（所有 vs 至少一个）、覆盖语义（全部面积 vs 发生过一次）、时间基期（固定基期 vs 连乘）。 报告末尾裁决行与 JSON `status` 必须一致；程序校验不通过一律 UNVERIFIED，重试或披露不构成放行。

侧车里只有两条通道，选错通道 = 白写。 先把机制看准（下面三条是机制事实，不是推测）：

1. `issues` 是拦链通道，而且在这个门禁里 `severity` 写什么都等于 `hard`。
   侧车的 `issues` 每条都必须挂 `check_ids`（指向确已 failed 的必查项），而本阶段的四个必查项
   `task_fidelity` / `quantifiers` / `stochastic_semantics` / `model_assumptions` 全部在
   驱动的 `RESULT_CHECK_CATEGORY` 反推表里 —— 于是每条 issue 的 `category` 都会被反推成
   实质类（`task_interpretation` / `constraint_model` / `stochastic_model`），`severity` 一律 `hard`。
   写 `severity: "soft"` 或 `"info"` 完全不起作用，只是把「自认为它不重」写进去了而已。
   （本阶段是六个门禁里唯一四个必查项全被锁死的；别的门禁有未锁的检查项，soft 才可能作数。）
2. `advisories` 是不拦链通道 —— 这才是不改数值的登记类问题的去处（见下）。
3. 别拿通道当挡箭牌：实质缺陷塞进 `advisories` 就是洗白，驱动会按 category 判它不合规。

哪些进 `issues`、哪些进 `advisories`——判据是缺陷的实质，不是"感觉它重不重"：

| 缺陷的实质 | 去哪 | 后果 |
|---|---|---|
| 判据/约束/量词/随机过程/实现/前提/证明本身的缺陷 | `issues`（category 填实质类） | 拦链 → 退回 analysis 改 |
| 建模报告自身的登记数不符、自述与正文不符、命名前后不一、证据摘录陈旧、编号串位、交叉引用指错、措辞过强 | `advisories` + category `report_wording` | 不拦链，且路由回 ② 建模设计（写那份报告的阶段）—— 下次回退到 ② 时会随回执交给它 |
| 论文侧（写成稿之后的）措辞/版式/图 | `advisories` + category `claim` / `presentation` / `diagram` | 不拦链，分别转给 write / format / drawio |

报告层 vs 论文侧别填混：建议说的是建模报告（`reports/ANALYSIS_MODELING_REPORT.md`）里的话
→ `report_wording`（回 analysis，那句错话才真的被改掉）；说的是论文（`paper/`）里的话
→ `claim`/`presentation`。填错方向的代价：拿 `claim` 送它去 write，而 write 不改编报告 ⇒
报告里那句错话留着，下一轮门禁重新记一遍。

写 `advisories` 的要求（两条驱动都在校验，不合规整份裁决判 `verdict_malformed`）：

```json
{"id": "adv-xxx", "category": "presentation",
 "evidence": "§17.5(r) 要点③ 写『逐位一致』，而脚本 stdout 打印 `⇒ 一致 ? False`",
 "fix": "把该句改为…",
 "why_not_blocking": "只动 §17.5(r) 的一句自述措辞，不改任何数值、方程、判据或交付件"}
```

- `category` 只能是 `claim` / `presentation` / `diagram` / `report_wording`（这条守卫与 `12Rubric-final` 的轻微项同源）。
- `why_not_blocking` 必填：一句话说清"为什么不影响交付"（哪个数值/方程/判据不会变）。
  写不出来，说明它其实是实质缺陷 —— 那就该进 `issues`。

代价：把登记/自述类塞进 `issues`（哪怕它自己在
evidence 里写着「本身不构成回退理由」），会被升成 must 拦链 —— 真正该拦的只有一条，
白拖一轮（analysis 20 分钟 + review 23 分钟）。"捎带"这类项时，走 `advisories` 才是捎带；
塞进 `issues` 是把它升级成拦链项。

## 评审的三道检查（逐子问题执行）

### ① 数学正确性

- 公式推导是否自洽、量纲是否一致、边界/极限是否合理、是否数值可解。
- 变量/符号是否与报告中的符号表一致、无同名不同义。
- 若声称"最优/唯一解/闭式解"，是否真有依据（如单调性、凸性）而不是拍脑袋。
- 数学检查不依赖具体题域：任何题（物理机理、经济优化、统计判别…）都按"公式→量纲→边界→可解→符号一致"这条通用链核对。
- 结构 vs 蛮力审查（防"只会枚举"，细则见 norms「数学结构挖掘与理论深度」）：可证结构（单调/凸/可分/对偶）没被用来缩小搜索或保证最优 → REVISE 补结构论证；引理/命题没被用到 = 装饰，退回或删；定理/最优性声明证明要点不能逐行复核 → 视为未证声明，降级为观察；几何/物理判据靠离散采样却没给"为何采样充分"的解析依据 → REVISE。
- 最优性措辞-证据自洽（对照 norms「省者胜出/最优性论证分级」）：声称"最优/全局最优/无更优"必须能指向 (i) 可证削减 + 对充分集穷举 或 (ii) 有界 ε-最优 的证据；只给"本流程搜索/代表值"只能表述为 (iii)/(iv) best-known。另查"搜索到的盆之外，是否还有只能由结构论证排除、却未被排除的候选策略族"（如被自设 τ 下界/整机指派/固定走廊截断掉的盆）——存在且未做松弛审计或结构排除证明 → 判 REVISE。
- 剪枝与判据 scoping 自洽：①声称"不硬剪枝/只低优先级"但解空间实际被可行性/探针收缩排除 → 无解析不可达证明则判 REVISE（对照 norms「剪枝与断言一致性」）；②判据若只统计"单体独立成立"（单烟幕单独遮满目标轮廓），须显式声明"不考虑多体空间联合覆盖"——有协作可能而未声明/未实现每时刻投影并集覆盖 → 判 REVISE（对照 norms「多体空间协作判据 scoping」）。
- 数学推理验证（新增，防"定理看着对其实假/有洞"）：对每个数学声明（引理/命题/最优性/单调/凸性/判据充分性/上界），做两层独立验证，不是"扫一眼觉得顺"：
  1. 独立反证复核：review-math 需 spawn 一个只做"试图推翻/独立重推"的子 agent——对一个数学声明，主动尝试找反例、构造能推翻它的输入、或独立把证明要点重推一遍；能给出"这里第几步不成立/少前提"才算通过。找不出反例也要说明"试图反证哪些情形未破坏"。不进行反证尝试、只说"合理"的，视为未验证。
  2. 数值交叉探测：凡声明可被计算探测的（单调性→在网格上抽查序关系；凸性→抽查中点不等式；判据充分性→把"边界判据判真"与"稠密/真值判据"在代表性随机几何上对照；上界→与小规模精确解对照），必须列出探测方式与结果；声称的性质在探测中若出现反例，判 REVISE。数值探测是"定理的工程兜底"，与解析证明互补，两者都要。

### ② 题意权衡与交付覆盖

逐条核对题面给定条件、模型约定和目标函数。硬约束必须来自题面、成立的物理数学前提或明确披露且有依据的建模约定；软代价须有口径和敏感性说明。

- 单组、全零、相同决策或边界解只触发诊断，不自动失败。核查可行性、目标项、单位、权重来源与基线结果。
- “新增约束会改变解”不能证明原模型错误。只有原模型确实遗漏有依据的必要约束才返修；禁止为制造更复杂/更好看的结果添加成功率、分组数等门槛。
- 按题面逐项检查交付覆盖。无依据的确定结论必须降级；有依据的不可识别结论或带条件方案可以通过，但需明确证据限制与补数据要求。
- 漏答、未尝试验证、指定文件缺失要指出具体影响和返修方式；不把数据不足解释为必须制造结论。

假设节卫生（防"假设翻倍/把必然当假设"）：建模报告/论文的假设清单若 ≥2/3 是题面给定条件的重述，或把物理/数学必然（如"高度>0 才能起爆"）与判据/计时/计数口径错放进"假设"节 → 判 REVISE：要求按 norms「假设节编制纪律」做三来源标注（题面给定/物理必然/建模约定），只留 3–6 条真"建模约定"，每条带"放宽影响哪一问"；判据口径移正文判据定义处。注意判据方向：只有缺了必要前提才 REVISE，不是"假设多"就退——为压数砍掉承重约定同样不合格（那是假精简，会真伤结论）。

建模纪律两条（对照 norms「建模纪律两条」，逐条判）：① 风险度量有效性：若模型用 CVaR/方差等风险项，核验它在本数据上是否真能区分风险中性/厌恶（尾均值与均值差是否 > 求解 gap 的利润量级）；若退化成均值的单调变换 → 判 REVISE，要求换度量或如实声明"不具区分力"，不接受把"坏情景被压平"当优点。② 强/弱解读：题面约束有强读（面积覆盖/每机计数）与弱读（发生过一次/总计）时，主方案必须按强解读实现；弱读只能作对照并披露违规计数。若建模用弱读当主方案 → 判 REVISE。

判据/近似的解析合理性审查（新增，几何/物理/口径类适用）：若某核心判据或结论靠数值采样/枚举/近似得到（如几何遮挡用离散轮廓点检测、判据用稠密档收敛），评审必须检查建模是否给了解析层面的合理性论证（凸性、单调性、边界/最坏情形、或"为何采样充分"的说明），而不是只堆数值档数。能补一个"若 A 成立则 B 必成立"式的引理/几何论证的，应要求补上；纯数值近似应在正文明示是近似并给收敛/误差依据。"算得对"≠"能讲清为什么对"，后者是竞赛与高分差的关键。

限制解空间的结构假设审查（细则见 norms）：压复杂度用的结构假设（"每机至多服务一个对象""整机指派不拆弹""分层决定"等）必须同时具备 ①机制/物理理由 ②放宽版测试 ③论文披露；缺任一 → FAIL 退回补。
对照 `LITERATURE_DIRECTION.md` 的机理基线，回答：

- 每问的主变量/因果方向是否与领域机理一致？特别警惕"数据驱动把衍生/辅助量当主变量、把机理主变量挤成不显著"。
- 对判别/分类类子问题：特征是否做了领域要求的校正/去偏（如测序 Z 值对 GC、读段深度的回归去偏；批次/质控变量控制），而不是裸用原始特征硬拟合？
- 对时间/到达类子问题：是否把"到阈值时间/删失/纵向"当成了生存/事件时间结构处理，而不是当成普通回归或插值？
- 声称的"显著性"是否在机理上可解释；若出现与机理矛盾的显著/不显著，评审必须标记并给出核查方向（是否共线性、样本不足、口径错误）。

### ④ 数据严谨性预检（建模前，防"数据口径跑偏"）

在建模方案定稿前，针对数据不严谨的常见教训逐项预检。以下任何一项若不明确或疑似有误，判 FAIL 并要求 3analysis 澄清后再审：

- 分析单位（unit of analysis）是否清晰：纵向数据必须说清"统计单元是谁"——是按独立对象还是按重复记录？结论与性能指标必须在同一单位上解释，禁止把"记录级"和"个体级"混在一起（如声称个体级性能却用记录级样本）。
- 样本量是否够撑结论：对判别的阳性样本数与类别数显式评估（如每类阳性是否 >20、EPV 是否过低）；不足则必须降级说法（"仅报告描述/规则，不强行拟合"），禁止在小样本上宣称高 AUC/高精度。
- 标签口径是否唯一且说明：若数据有多个标签（如"染色体非整倍体"与"胎儿健康"），必须明确用哪个、两者不一致怎么处理；禁止两个口径混用。
- 泄漏风险是否在设计上排除：按个体分层划分训练/测试；特征中不得包含"结果本身/事后信息"（如用出生结局当输入特征）；分组/归一化只在训练折上学习。
- 缺失/异常处理是否写明并做敏感性对照。

（此预检在代码前做的是"设计层"检查；代码跑完后 6Robustness 再做"结果层"的可信度审计——若结果指标异常乐观，回查这里的泄漏/样本设计。）

## 执行方式（关键：职责拆开、各用独立子 agent，防上下文稀释）

设计原则：**不要在一个上下文里同时审"数学 + 题意 + 机理 + 数据"四件事**——审查维度堆在一起会互相稀释，每个都审不深。正确做法是每个维度 spawn 一个只盯该维度的独立子 agent，各写各的结论，最后汇总。

1. 先落骨架（§六·6.1）：开工第一步就写 `MODELING_REVIEW_REPORT.md` 与 `.verdict.json`（`status=UNVERIFIED`、`issues: []`），**不要等查完再写**。子 agent + 复算极容易吃光整段时间；产物留到最后写，一旦跑到没气现场就是一片空白——驱动只报「阶段未成功完成：failed」，读不出任何结论，人也没法据此决策。骨架是占位不是结论，每查完一维必须回填。
2. 当前会话只做汇总与裁决，不亲自逐问深审（避免"写模型的人审自己"+ 上下文过载）。**尤其不要自己造求解器/复算脚本去验证子 agent 的结论**——那是子 agent 的活，而且它会在关键路径上串行烧时间：报告只有你能写，你的复算却有替代品。反例：主 agent 自写 ODE 求解器并反复调试，吃掉本阶段大半时间，四个维度一个都没定稿。要抽查就用几分钟内跑得完的短脚本，只验子 agent 给出的具体数字（如 `ROUND_HALF_UP(0.14995,4)` 这种一行式），不重做它的推导。
3. 用 **Agent 工具并行 spawn 4 个独立子 agent**，每个只领一个维度：
   - `review-math`：只审 ①数学正确性（公式/量纲/边界/可解/符号一致）
   - `review-intent`：只审 ②题意权衡（目标/约束/退化解/保障率是否硬约束）
   - `review-mechanism`：只审 ③领域机理（对照 LITERATURE_DIRECTION 的主变量/因果/去偏）
   - `review-data-design`：只审 ④数据严谨性预检（分析单位/样本量/标签口径/泄漏设计/缺失）
   给每个子 agent：对应那条检查的原文 + ANALYSIS_MODELING_REPORT.md +（mechanism 那个还需）LITERATURE_DIRECTION.md；要求只输出该维度的 PASS/FAIL/修改清单，**禁止越界评其它维度**。
4. 每回来一维就回填一次骨架报告（§六·6.1），别等四份齐了再一起写。四份齐了再定稿裁决：任一维度判 FAIL 且有具体证据 → 整题 REVISE（把对应维度的修改清单作为回执）。
5. 复查仍 FAIL 的维度：写明分歧，转黄灯由用户选「再试一次 / 回退到某阶段 / 接受并披露」——本阶段不再自动重试。

## 门禁动作

- APPROVED：在 ANALYSIS_MODELING_REPORT.md 末尾追加"建模评审结论：APPROVED"，然后才放行 3analysis 的"代码实现任务清单"给 5coding。
- REVISE：把 MODELING_REVIEW_REPORT.md 的修改清单作为回执，退回 2Modeling-design 修改 → 重新跑本门禁。本阶段一个阶段只跑一次：这一轮仍 FAIL 就转黄灯（`awaiting_user`），由用户在面板上选「再试一次 / 回退到某阶段 / 接受并披露」。把无法调和的分歧写清楚，供用户判断。

## 阶段边界

- 只评审建模方案与机理，不写代码、不跑数、不改论文。
- 判定必须给"具体怎么改"，不允许只写"模型不行"。
- 不擅自改 3analysis 的产出文件；修改由 3analysis 阶段按回执执行。
