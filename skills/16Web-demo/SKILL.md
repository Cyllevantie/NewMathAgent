# 交互式系统开发（16Web-demo）

> 通用执行纪律（增量返修 / 缩比预估 / 分段落盘 / 方法标记 / 返修只动清单内）见 `../_references/stage_discipline.md`。
> 本阶段适用：一（增量返修，含 1.1 探针复用）。
> 探针/量测脚本要复用（通用纪律 一·1.1）：本轮写的取证/量测脚本一律留在 `_tmp/`
> （另有散落的在 `tmp/`，两个都要看）；下一轮开工第一步 = `ls _tmp/ tmp/` → 把上一轮
> 为同一批对象写过的脚本先原样重跑（秒级，确认数在当前版本里还成立）→ 只对本轮新出现或改过
> 的对象写新脚本。别每轮从零重写 —— 全链 776 个自写脚本里 **683 个（88%）只被用过一次**
> 就再也没人碰。复用探针 ≠ 跳过复核：探针只是取证手段，判定仍逐条对着当前版本做。

把建模结果做成一个真正能跑、参数可调、结果实时更新的单页 Web 工具。不是静态展示页、不是"为了截图拼的界面"——是评委/用户打开就能用的交互式系统。

## 定位与边界

- 本 skill 负责：交互式系统的功能逻辑 + 真实数据 + 交互流畅 + 结构清晰的 UI。
- 本 skill 不负责：UI 视觉美化（配色/动效/排版精修留给用户后期设计）；不产生"新的分析/新的数值"——系统里的每个数都能溯源到 `reports/RESULTS_REPORT.md` 或 `code/outputs/*.json`。
- 已接入正式链：作为 verify（验收、PDF 定稿）之后的末段阶段运行——PDF 先产好、用户可随时打开，web demo 在不影响论文的前提下补充交互落地。凡题含"条件/参数→结果"式可执行结论（推荐/决策/优化/预测/判定/评价类）都应产出；纯机理推导/纯证明/无可交互参数的题则跳过并在 `DEMO_REPORT.md` 说明原因。

## 触发条件（什么题适合做）

适合：有"条件/参数 → 建议/结果"式可执行结论的子问题。典型：

- 推荐/分组类：选 BMI 区间 → 显示推荐时点
- 决策类：选参数 → 显示最优方案/分组
- 判定类：输入指标值 → 显示三态判定/转介
- 预测类：调参数 → 实时重算预测曲线
- 优化类：改约束/权重 → 显示最优解变化

不适合（做了也白做）：纯机理推导、纯证明题、没有可交互参数的题。若题不适合，说明原因并建议不做。

## 三条纪律

1. 功能优先：参数真的能改、结果真的实时重算、交互流畅（无卡顿/无假结果）。不是静态展示。
   - **图表必须响应输入**：任何与输入参数有关的图（折线/柱状/曲线），都必须在输入变化时实时更新，并带当前状态指示——如"当前 q 位置的竖线/高亮点"、"当前选中项高亮加粗（其余变淡）"、"游标标记当前取值"。**禁止画一张静态图**让用户调了参数图却纹丝不动——那是假交互。
2. 数据真实：系统里每个数值、每条曲线都来自 RESULTS_REPORT 或 outputs，可溯源；DEMO_REPORT 里写清数据来源。**禁止**前端"编一个看起来对的数"。
3. UI 留白但结构清晰：不花时间做精美视觉；但 DOM 语义化（`<select>`/`<input type=range>`/结果区有 id）、CSS 用变量（`--primary` 等）集中定义，让用户后期改主题只需动一处。结构要让"换皮"很容易。

## 动态三维模型（主视图的默认形态）

**判据（这张表决定要不要三维，不是"看着办"）**：

- **必须三维** —— 模型里带空间结构：曲面（膜面/温度场/水位）、场/体（浓度/应力/密度分布）、轨迹（光束/质点/机构运动）、三维点云、参数曲面（响应随两三个参数变化）。数学建模题绝大多数都落在这里 ⇒ **每一个**带空间结构的子问题/页签都以数据驱动的三维动态模型做主视图——**不只首屏那一个**（首屏只是排最前的那个；用户 2026-10-16：「这个网页好像只有第一个题有，别的题怎么没有」）。"图案/分区/反演"这类视图各自去想它们的空间坐标：轨迹的第三维是时间、分区的第三维是判别量、反演的第三维是残差/灵敏度面。原有二维曲线**不删**（谱线/剖面能回答三维答不了的问题），降为同页辅助图。
- **可以不三维** —— 结论天然是一维曲线/二维散点、参数与空间无关的判定/查表/排序题。此时在 `DEMO_REPORT.md` 里写一行 **`三维豁免：<一句理由>`**（固定前缀，交付检查按它放行）。
- **不许为了三维而三维**：编一个与模型无关的三维场景，与前端"编一个看起来对的数"同罪。
- **与论文静态图同视角**：论文里的物理立体图由 ⑦ 第五类 `fig_geometry_3d` 生成
  （规范见 `skills/7Route-diagram/references/physical-3d.md`）；网页交互如果画同一对象，
  用 Route B `*.scene.json` 里的 `camera.azim/elev/zoom` 初始化视角，别论文一个角度、网页另一个。

**四条硬要求**（每条自测时都要过一遍）：

1. 可转：拖拽旋转 + 滚轮缩放真的生效（`scene.attachOrbit`），不是预渲染图片轮播。
2. 可调：参数滑块/选择器 → 场景重算重画。数据真实纪律不松动 —— 面上每个点要么来自 `results/*.json`、要么按论文模型前端现算（现算的要进 `runSelfTest()` 与落盘值对账，容差写进 DEMO_REPORT）。
3. 有指示：当前状态画在**三维场景里**（游标点/竖直读数线/高亮轨迹），不是只在旁边的数字区。
4. 有时间/相位维度就必须能动：播放/暂停/定格 + 时间轴可拖。播放控制做成**显式 ▶ 播放 / ⏸ 暂停按钮**（不要用勾选框承担播放职责），**播放时时间轴滑块要自己跟着走位**（用户 2026-10-16：「缺少个播放键让他自己滚动进度条的那种」）。**时间由你传入**（引擎没有时钟，不许 `Date.now` 驱动帧）；`prefers-reduced-motion: reduce` 时默认暂停；**首帧同步先画一次**，`requestAnimationFrame` 只驱动后续帧 —— 无头截图可能拍到 rAF 之前的空白画布。
5. **画布尺寸幂等**：重画流程（任何一次重画）绝不许改画布的 `width/height` 属性或 `style` 尺寸——尺寸只在初始化时定一次，重画只 `clearRect` + 重画。**这条有无头测不到的盲区，必须专门实测**：截图的浏览器 dpr=1，任何"每次重画 ×dpr"的错误在那里都是 ×1、完全隐形；用户常见 120%/125% 缩放下才会炸。自测加一条：`--force-device-scale-factor=1.25` 下连画 ~40 次，断言画布尺寸纹丝不动。真实事故（2026-10-16）：2D 画布的公共入口按**裸 id** 填尺寸表、查询时却传了选择器 `"#id"` ⇒ 查不到就回退成自引用 `[el.width,…]` ⇒ 用户拖两下三维，下面的曲线图被乘成百万像素宽、整个容器被撑爆；再拖几十次超过浏览器画布上限，**图整块变白**。三个症状（乱变/拉伸/消失）其实是同一个 bug。
6. **交互隔离**：拖相机、播动画这类"只动三维"的操作，不许牵动与它们无关的图 —— 其它图要么不重画，要么（因为幂等）重画后逐像素相同。判据：播动画时去数一数，每帧被清的画布应该只有该动的那些。

**引擎（`skills/16Web-demo/assets/scene3d.js`，零依赖 Canvas 2D，约 17 KB）**：

- 读该文件，把**整段原文**原样内联进 `demo.html` 的 script 块 —— **一个字符都不改**（不许改缩进、不许重排）。交付检查按整段原文比对；回归夹具 `regression/demo3d_check.js` 对它做行为测试。要改观感走 options；真要改引擎就改源文件、把版本号 +1、重跑 ⑯ —— **不要在产物里就地改**。
- 不许 CDN、不许自造轮子、不许把引擎副本放进 `demo/`（只有 `demo.html` 里内联的那一份）。
- API 速查、两种计算架构（前端重算 / 预计算查表）接数据的写法、性能预算与降格顺序、hash 深链约定：`skills/16Web-demo/references/scene3d.md`。
- 量级差的题（膜位移 µm 对半径 3 cm）用 `scene.setScale({z: 200})` 放大**显示** —— 刻度/色标/标签保持真实值，引擎会自动落一行"视觉放大 ×N"注记；把放大量藏起来就是把显示当数据。
- `bounds` 给一次就粘住，跨参数档/跨帧不许重设（自动取景会把振幅变化归一化成"没变化"，两张截图也不可比）。
- 性能：每帧四边形 ≤ 5000（引擎默认 `maxQuads`，超了自动降采样并在 `stats.stride` 里如实标注）；动画建议 40×40 左右。拖动/滚轮只重投影 —— 贵的数据重算缓存在闭包里，参数变化才重建。不许静默掉帧，实测帧时间写进 DEMO_REPORT。

## 计算架构决策（关键：决定"流畅"与"真实"）

先判断目标结论的计算复杂度，二选一：

A. 前端重算（公式简单时优先）：插值、查表、线性/多项式、简单 logistic/指数、闭式解——用 JS 在前端直接算。最流畅、单文件、离线可用。

B. 预计算查表（公式复杂时）：需要 python 拟合/优化/数值积分/枚举才出的结果——用 python 预计算一组参数网格 → 结果，存成内联进 `demo.html` 的 JS 数据块，前端查表 + 线性插值。要保证网格够密、插值误差可忽略，并在 DEMO_REPORT 里说明插值方法。

**绝不做**：为了"看起来能算"而让前端显示与真实模型无关的假公式。若某参数无法在前端真实重算，就改为"预计算查表"，或明确标注"该参数为演示档位，非连续可调"。

模型有 ≥2 种合理可视化/交互形态时（如三维曲面 vs 二维曲线、参数滑块 vs 情景预设），
先按 `../_references/stage_discipline.md` 八建 `.fma_panel_lock`，再用 2–3 个子 agent 各写一份
**一页设计方案**；收齐后删锁，再动手写 `demo.html`：

- 每个子 agent 只写 `_tmp/demo_design/<n>.md`：主视图、数据映射（哪个输入 → 哪个输出）、

## 工作流

1. 读结论与数据：读 `reports/RESULTS_REPORT.md` 对应子问题 + `code/outputs/*.json`，确定"哪些是输入参数、哪些是输出结论、输出怎么随输入变"。
2. 定计算架构：按上面 A/B 二选一；复杂公式用 python 预计算网格，写清插值。
3. 写 demo/：一个 `demo/demo.html` 写完 —— 数据块、逻辑、样式、结构都在里面（想清楚再写，别先生成一堆文件再合并）。**开工先读** `skills/16Web-demo/assets/scene3d.js`（引擎全文，逐字内联）与 `skills/16Web-demo/references/scene3d.md`（API 与惯用型），再写数据块/逻辑/样式/结构。
4. 自测：本地用浏览器打开 `demo/demo.html`，逐项验证——每个输入改动都触发正确结果更新、无 console 报错、数值与 outputs 一致。必查项：① 拖动/修改每个输入，对应的数字结果是否实时变；② 每张与输入有关的图是否随输入更新并带当前状态指示（竖线/高亮点/高亮当前项），不是静态图；③ 有没有任何"输入改了、页面某处却纹丝不动"的死角。**三维视图再过四条**：④ **每个**三维视图的每个参数档/预设都走一遍，`scene.stats()` 的 `skipped` 只许是 0（不为 0 说明有坏点被静默跳过，是数据缺口）；⑤ 拖拽转一圈 + 滚轮缩放，无 console 报错、无画面裂口；⑥ `runSelfTest()` 的输出（含与 `outputs` 的对账结果）原文抄进 `DEMO_REPORT.md`；⑦ **dpr 幂等实测**（无头截图 dpr=1，这类病**只有它抓得住**）：`msedge --headless=new --disable-gpu --force-device-scale-factor=1.25 --virtual-time-budget=8000 --dump-dom "file:///…/demo.html#…"` —— 页面里连画 ~40 次后断言**所有画布**的 width/height/style 尺寸纹丝不动（探针：`for(i<40) 重画();` 再把尺寸写进隐藏元素，grep 出来对账；写法见「画布尺寸幂等」那条的事故注）。⑧ **数据块点数与区间自检**：内联的预计算网格逐条查 min/max/越界计数，且"邻域半宽 8×ζf"这类**注记要与生成参数同源**（事故：探针里半宽被多乘一个 f0 ⇒ 1189 点里 648 点越界（340 个负频率），画布把越界点裁掉、肉眼零异常，只有自检能拦）。
5. 截图存档（交付要求，不是可选）：用 headless 浏览器给 demo 截图，存进 `demo/`，并在 `DEMO_REPORT.md` 里列出每张截图对应的状态。
   - 至少 **3 张**：①首屏默认状态（**若本页有三维主视图，必须用三维主视图**——它是附录 图 A1 的图源；
     已写「三维豁免」的题用该页主视图即可）；②拖到某个有代表性的非默认输入后的状态（要能看出数值/图随输入变了）；③（若有多个子问题/视图）切换/展开后的状态。
   - **三维视图先定格再拍**：动画不定格时两张截图抓到不同帧、不可复现 —— 用 `#…&t=<相位>&play=0` 定格、参数与相机角也全部走 hash（`&az=&el=&dist=`），截图命令照抄得出来。
   - 有三维视图时，截图里至少一张要**转过相机**或参数状态明显不同（转一度不算，要一眼看出转过去了）——这就是"可转/可调"两条硬要求的截图证据。
   - 命令里带上 **`--force-device-scale-factor=1.25`**（按常见 120%/125% 缩放拍）：它顺带让"每次重画 ×dpr 连乘"那类病在截图轮就露头（dpr=1 会把它完全藏住）。每个三维视图各拍一张主状态，别只拍首屏那个。
   - 命令（无需装 Playwright；先把 `demo/demo.html` 的绝对路径求出来再拼 `file://` URL，
     别在提示里留 `<绝对路径>` 这样的占位符直接抄）：
     - Windows：`msedge --headless=new --disable-gpu --window-size=1400,900 --screenshot=demo/shot_1_default.png "file:///<abs>/demo/demo.html"`
       （Edge 不在 PATH 时用 `"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"`）
     - Linux：`chromium --headless=new --disable-gpu --window-size=1400,900 --screenshot=demo/shot_1_default.png "file:///<abs>/demo/demo.html"`
       （或 `google-chrome`；容器里加 `--no-sandbox`）
     - macOS：`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new …`
     - 真一个浏览器都没有时：写一份 `demo/自测记录.md` 说明"没有可用的 headless 浏览器"，
