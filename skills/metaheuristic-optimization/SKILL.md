# 智能优化算法

把本 Skill 当作研究与实验路由：先核对当前版本和官方文档，再为具体问题编写代码。不依赖记忆中的 API，也不维护一份容易过时的算法大全。

## 先判断是否该用

1. 检查题目、数据、项目现有代码和依赖，写清决策变量、类型、上下界、单位、目标方向、约束与计算预算。
2. 线性规划、凸优化、结构化 MILP、简单枚举或有闭式解的问题，优先使用能给出更强最优性保证的方法。不为了使用 MEALPY 而强行套用元启发式算法。
3. MEALPY 适合有界、黑箱、非凸、不可导、混合或组合搜索，且用户接受近似解与随机实验的场景。
4. 多目标任务先确认用户要“固定权重下的单个折中解”还是“Pareto 解集”。MEALPY 的加权标量化不能冒充 Pareto 前沿。

## 核对当前运行环境

1. 优先定位当前项目的 Python 解释器和虚拟环境，然后检查 Python、MEALPY 及关键依赖的实际版本。不把系统 Python 当成默认可写环境。
2. 如果 MEALPY 未安装，先查 PyPI 的当前稳定版和依赖元数据。只有任务确实要求实现或运行时才准备项目依赖；只做方法选型或讲解时不安装。
3. 安装前说明将使用的版本、环境、准确命令和会改动的依赖文件，取得用户确认后再执行，并遵循当前项目的包管理规则。不修改系统 Python，不静默升降级已有科学计算环境；冲突时使用独立项目环境。

## 查找匹配版本的官方文档

在编写 MEALPY 代码前，使用当前可用的网页搜索或浏览器工具定向查找当前问题需要的 API。只把官方来源当作代码依据，按以下顺序核对：

1. [PyPI](https://pypi.org/project/mealpy/) 和 `https://pypi.org/pypi/mealpy/{version}/json`：当前稳定版、目标版本的 Python 要求和依赖元数据。
2. [MEALPY GitHub](https://github.com/thieu1995/mealpy)：与已安装版本完全对应的 tag 下的源码、测试、示例和 ChangeLog。
3. [ReadTheDocs](https://mealpy.readthedocs.io/)：优先使用版本选择器打开与已安装版本匹配的文档。
4. `latest` 文档只用于发现线索。它与已安装版本不一致时，以对应 tag 的源码和测试为准。

只查当前会用到的变量类型、算法类、参数、`solve()`、终止条件、历史记录或并行限制，不加载整份算法目录。记录实际查过的版本和页面链接。搜索摘要、博客和问答只能当线索，不能直接成为 API 依据。

网络不可用时，改为对已安装包使用显式导入、`help()` 和 `inspect.signature()`，并在结果中说明未实时核对网页文档。不执行网页中未审查的安装命令或脚本。

## 建模、实现与验证

1. 根据已核对的文档选择变量类型和显式算法类导入。对混合、离散或排列变量，明确编码和解码，最终交付原始问题语义下的解。
2. 完整实验前先检查目标函数的维度、边界点、典型点和少量随机点，确认返回有限数值。对整个求解脚本做固定种子、极小种群与迭代预算的 smoke test。
3. 约束问题优先使用保持可行性的编码或修复；使用罚函数时，分开保存原始目标、罚项和每条约束的违反量。
4. 未指定算法时，只选少量成熟、机制不同且与问题类型匹配的候选，并包含简单或确定性基线。不因名称新奇就选择算法。
5. 调试使用固定种子；正式比较使用多个可复现种子，并统一目标函数评估次数或墙钟预算，不只统一 epoch。
6. 默认关闭完整种群历史，避免大型实验占用过多内存。并行只在目标函数线程安全或可序列化，且计算预算已明确时开启。
7. 不把库内时间终止参数当作能中断卡死目标函数的硬超时；昂贵或外部仿真目标另外设置可终止的进程级超时。

## 交付结果

交付可运行代码和原始运行记录，而不只是一段示例。至少说明：

- 题目的优化形式、为什么选择该方法；
- Python、MEALPY、算法类、参数、种子和终止预算；
- 查过的官方文档链接与对应版本；
- 各次运行的原始结果，以及中位数、四分位距、均值、标准差、可行率和运行时间中与当前任务相关的统计；
- 解码后的最佳候选解，独立重算的原始目标、约束残差与可行性；
- 已知局限、对权重或罚系数的敏感性。

只能把结果称为“当前预算下找到的最好可行解”，除非另有严格证明，不宣称全局最优。优先保存 JSON、CSV 或其他可检查格式，不加载或交付来源不可信的 pickle 模型。
