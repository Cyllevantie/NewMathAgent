# 大流程图规范：问题路由树 / X 问泳道

> 适用：`fig_roadmap`（论文图 1「分析流程图」）。它说明建模、方法、操作与判断，
> 不是代码 I/O，也不是把正文一句话画成三格直串。
> **停用**：时间轴版式；`roadmap-5band` / `roadmap-3phase` / `framework-3col` /
> `stageflow-3col` / `taskflow-land` 五个线性模板。

## 0.0 先看用户给的参考模板

`assets/roadmap_templates/` 下有用户确认的 `flow1.png`（问题路由树，按问分色；
当前示例是 Q1–Q4，问数由题面决定）与 `flow2.png`（X 问泳道，问数不固定）。生成顺序：

1. 有真实条件分支、能路由到各问 → **优先按 flow1 的“路由树 + Q 分色 + 结果文档”生成**；
2. 各问并列、没有真实路由条件，或 flow1 在当前页面装不下 → **按 flow2 的泳道生成**；
3. 两者都不适合时才回退到紧凑 route tree，并在 `DRAWIO_REPORT.md` 写明为什么。

模板只提供**结构与阅读顺序**，不提供固定坐标。每题的输入、真实分支、支链数量和结果
文档都不一样，**构图必须按本题重新设计**；`flow1.png` 不是要逐像素复刻的底图。
**图中数值必须逐项取自当前 `reports/`**，不得抄参考图旧值。
每个问的颜色取 `config/visualization.json` 的 `question_palette` 对应项，不要从 PNG 取色；
问数超过现有 Q1–Q4 时按同一语义色阶补色，不要把「四问」当成固定结构。
`../scripts/flow1_roadmap.py` 是本题的一份参考实现（内容槽位在文件顶部）；可以改写、
重排或另写生成器，但必须满足 §5 硬规则与 §6 的 8 条自检。它输出
`figures/fig_roadmap.drawio`，再用 `check_layout.py --flow` + draw.io 导出 PNG/PDF。

## 0. 字体 / 语言 / 宽度：跟论文其他图完全一致

`fig_roadmap` 不是独立画风。开工先跑：

```bash
python skills/figure-studio/scripts/resolve_context.py --write
```

按它解析出的 `language` / `font` / `width_mm` 画：中文论文 → 微软雅黑、中文标签、160 mm；
英文论文 → Arial、英文、183 mm。字号与数据图同一套（正文 ≥9 pt，最小 8 pt）。
**图内不混用中英文**（变量、单位、专有名词除外）；不要沿用旧模板的 16 px 大字号或 954 px 画布，
也不要因为换了结构就单独换字体。`fig_roadmap` 与数据图、其他示意图放在一起时，字体/字号/语言必须看不出差别。

**按最终印刷宽度定画布，不要按屏幕稿缩**：中文 160 mm ≈ 605 px（96 dpi），路线图占
0.85–1.0 栏宽时画布 515–605 px；节点正文 12–14 px（≈9–10.5 pt），标题 15–17 px。
不要画 1500 px 的屏幕稿再塞进 160 mm —— 10 px 字会缩成约 3 pt；
也不要沿用 954 px 竖版 + 16 px 字再整体缩到 0.85 栏宽（≈6.5 pt）。

## 1. 先定结构，再动笔

从 `reports/ANALYSIS_MODELING_REPORT.md`、`reports/RESULTS_REPORT.md`、`reports/FIGURE_PLAN.md`
和题面里列出四类东西：

- 输入：题面给的数据、序列、几何、初值；
- 共用骨架：模型方程、边界、离散、线性求解；
- **真实条件**：时间窗、物性是否随 C/T 变、是否收缩、是否复用前一问的解；
- 各问各自的方法与关键结果，以及检验。

然后二选一：

| 条件 | 结构 |
|---|---|
| 存在至少一个真实条件，能把各问路由开 | **问题路由树**（首选） |
| 各问是并列切片，没有真实路由条件 | **X 问泳道**（备选） |

没有第三种。不要退回五带/三阶段/三栏/横版流水线；不要画时间轴。

## 2. 问题路由树（首选）

拓扑（自上而下，或自左向右）：

```
开始（对准输入组中心）
  → 输入组（3–5 个平行四边形，按题面实际输入，母线汇入）
  → 共用模型容器（容器内 4–6 个小框：守恒基准 / 控制方程 / 边界 / 离散 / 物性 / 事件）
  → 条件菱形链（每个菱形只问一个真实二选一）
       ├─ 是/条件 A → 问 A 支链（3–5 个处理小框 + 1 个结果文档）→ 结束
       ├─ 否/条件 A → 问 B 支链（含两项校核）→ 结束
       ├─ 是/条件 B → 问 C 支链 → 结束
       └─ …（问数由题面决定，不固定四问）
```

> 上面的 Q1–Q4 是 2026A 的示例。换题时先数题面有几个问、有几个真实二选一，
> 再决定支链数；**不要为了凑“四问”把两问拆成四问，也不要少画一问**。

规则：

- 每个菱形出口必须有真实标签（「是 · 预热段」「否 · 全过程」「是 · 加收缩」）；
  没有真实二选一就不画菱形，改画处理框。
- 每条支链是一列**独立小框**，一个框只放一个事实；不要把「方法 + 判据 + 结果」塞进一个大框。
- 支链末端用文档形放关键结果；每条支链各自有结束胶囊，对准末框中心。
- 共用模型容器是**容器**，里面的每个要素要有自己的小框；容器本身不加正文。
- 输入组、模型容器、支链列之间用母线/短正交线连接，不画 N 条斜线。
- 输入汇流要读成「大括号」，不是四条卡片下划线：母线落在卡片下方 ≥8 px，
  每张卡一条可见竖向引线（≥6 px）落到母线，再由母线中点一根主干进入模型带。
  母线贴着卡底（≤6 px）在渲染图里会与卡的描边叠成下划线，看不出“汇入”。
- 主干**允许直接穿过**容器虚线边：虚线是分组边界，不是墙。不要为了避让虚线去
  开白色缺口或把一根箭头拆成两段（拆完只剩两截短杆，更像断线）。
- 图宽按 §0 定（中文 160 mm 折 515–605 px；英文 183 mm 同理折算），本节不另设画布宽度；
  支链多时按列排开，列间距 20–35 px（约 1.5–2.5 倍正文字号）。
- **按一页 A4 的长宽比设计**：目标 `W:H ≈ 0.68–0.71`（A4 210×297=0.707；
  160 mm 正文宽时高约 226 mm）。不要画成 0.59 那种“窄长条”：宽度不够时先加宽列/
  拉开横向间距，而不是只往下堆框；若确实放不下，才缩内容/减框，并在报告里说明。

### 2.1 样式令牌（参照 flow1 的比例，不照抄它的槽位）

`flow1.png` 是**屏幕稿**（按 160 mm 置入正文只有约 3 pt），不能照抄像素；能抄的是
与字号无关的比例：

| 项 | 目标 | 为什么 |
|---|---|---|
| 处理框 | **一个框只放一个事实，一行字**；需要两行就拆成两个框 | 两行同字号会把“方法 + 条件”挤成一团，读者分不清层级 |
| 文字占框宽 | 约 1/3–1/2，左右留白 ≥0.4 em | 参考图是“宽框 + 单行”，当前若文字占 3/4 就会显得像卡片 |
| 中轴 : 支链宽度 | ≥1.15 : 1 | 主干要读得比侧枝粗；反过来会像三列等宽 |
| 竖向间隙 / 框高 | 0.45–0.55 | 太小会把箭头挤成“獠牙”，太大则页面被拉长 |
| 箭头头长 / 间隙 | ≤1/3 | 箭头是连接符，不是装饰 |
| 菱形宽高比 | 3–3.5 : 1；文字一行 | 菱形是判断，不是小卡片；扁一点才像流程图 |
| 输入母线 / 卡底 | ≥8 px；引线 ≥6 px | 贴底会与卡描边叠成“下划线”，读者看不出汇流 |
| 容器带宽 / 画布宽 | 0.6–0.75（“窄头宽身”） | 不要每条带都撑满画布 |
| 标题 : 正文 | 1.6–1.8 : 1 | 当前 1.23:1 层级偏平 |
| 描边 | 低对比（与填充的亮度差约 50–60）；文字可用问色 | 深描边会抢文字的戏；问色承担识别 |
| 圆角 | ≈0.18–0.20 × 框高 | 全图统一一个值，不要标题圆、正文方 |

这些是**风格令牌**，不是槽位。输入几个、模型几个、几个菱形、几个结果文档，以及
**到底用几列、几层、2×2 还是泳道**，全部由本题的 `ROADMAP_DESIGN.md` 决定；
不要因为参考图有 4 个输入/3 个菱形就照填，也不要因为某份样例用了 2×2 就固定 2×2。

## 3. X 问泳道（备选）

拓扑（上→下）：

```
开始（对准第一条输入中心）
  → 输入组（3–5 个平行四边形，按题面实际输入）→ 共享模型链（5–6 个小框，横向母线）
  → X 条纵向泳道（X = 题目问数；每问一条，互不穿插）
       每条：问号 + 问名（着色标题条）
             → 窗口/输入（平行四边形）
             → 2–4 个方法小框
             → 1 个真实判据菱形（是/否）
             → 结果文档
  → 底部检验母线（5 个小框）→ 结束（对准检验组中心）
```

规则：

- 各条泳道用同一套纵向节奏（同层同高），读者可以横向比较；泳道数 = 题目问数。
- 每问的判据必须真实（用本题的阈值/时间点，不要抄示例里的 `t = 1800 s?`），
  出口标「是/否」；「否」回到本泳道的上游框，不跨泳道。
- 泳道之间不画交叉箭头；复用前一问的解用「输入：复用 Qx 解」的平行四边形表达。
- 顶部输入/模型与底部检验各用一条母线统一进出，不要每问各画一条长箭头。
- 图宽同 §0（中文 515–605 px）；各泳道等宽，间距 8–15 px。

## 4. 形状与颜色（语义固定，色值从 config 取）

本节只定形状与语义；具体色值一律从 `config/visualization.json` 的语义键取，不在文档里写死。

| 语义 | 形状 | 填充 / 边框（语义键） |
|---|---|---|
| 输入 / 数据 | 平行四边形 | `grid` 浅底 / `line` 边 |
| 处理 / 方法 | 圆角矩形（rx 8–10） | `grid` 浅底 / `palette[0]` 边 |
| 判断 | 菱形 | `grid` 浅底 / `warn` 边（仅阈值/异常/警示；普通二选一用 `line`） |
| 输出 / 结论 | 文档形（下沿波浪） | `box` 浅底 / `line` 边，文字 `ink` |
| 检验 | 圆角矩形 | `grid` 浅底 / `line` 边 |
| 开始 / 结束 | 胶囊 | `box` 浅底 / `line` 边 |

文字用 `ink`；不要把颜色当装饰。`warn` 只用于阈值/异常/警示，不拿它给普通分支上色。

## 5. 硬规则（违反任何一条都不算完成）

1. 图内不出现解释性旁白、图例、注、脚注、总结条；只留节点事实与分支标签。
2. 一个框里出现并列项，就拆成多个小框；大框只做容器。
3. 文字先量后画：框内文字水平、垂直都居中；放不下就加宽/换行/缩字号，绝不溢出。
4. 开始/结束胶囊对准首/末框中心；箭头垂直进入/离开。
5. 菱形只用于真实分支；出口标「是/否」或真实工况；不造伪判断。
6. 箭头从框边到框边；不悬空、不穿过实体框（容器虚线边允许穿过）、不绕圈、不在框内拐弯。
7. 同层同宽、同行同高、间距统一；不留大片空白。
8. 字号 ≥ 9 pt；节点文字 ≤ 2 行；长解释留在正文。
9. 一张图只讲一条阅读路径；支链/泳道是并列，不是第二套主线。
10. `fig_roadmap` 可以密（20–35 个框），但每个框只承担一个事实。

## 6. 生成后的强制自检回路

渲染 PNG 后逐框看，发现问题改脚本/XML 再渲染，直到下面 8 条全过；
每轮把「第几轮、改了哪些框、复验结果」写进 `reports/DRAWIO_REPORT.md`。

1. 框内文字块的水平中心与框中心偏差 ≤ 4 px（或 ≤5% 框宽）；垂直同理。
2. 文字不越框线，左右留白 ≥ 4 px；字号 ≥ 9 pt。
3. 起止胶囊对准首/末框中心。
4. 菱形都有真实出口标签，没有伪判断。
5. 箭头不悬空、不穿过实体框（容器虚线边允许穿过）、不绕圈。
6. 没有解释性文字、图例、注、总结条。
7. 并列项都拆成了小框。
8. 行列对齐、间距一致、没有大片空白。

`../paper-diagram/scripts/check_layout.py` 只能查溢出/重叠/穿盒，**不查文字居中**；
第 1 条必须靠打开 PNG 量框与文字包围盒。

如果走 SVG / 自绘而不是 draw.io：`text-anchor` 只认 `start` / `middle` / `end`。
把 `center` 写进去会被浏览器与 PyMuPDF 当成 `start`，表现是「文字从框中心起排、右半边溢出」——
2026A 的 D03 就栽在这上面，代码里写的是 `anchor="middle"`，底层却传成了 `center`。
**判据只能是渲染后量包围盒，不能只看代码里写了 middle。**
