# 竞赛论文撰写（LaTeX）

> 通用执行纪律（增量返修 / 缩比预估 / 分段落盘 / 方法标记 / 返修只动清单内）见 `../_references/stage_discipline.md`。
> 本阶段适用：一（增量返修，含 1.1 探针复用）、五（返修只动清单内）。
> **探针/量测脚本要复用（通用纪律 一·1.1）**：本轮写的取证/量测脚本一律留在 `_tmp/`
> （另有散落的在 `tmp/`，两个都要看）；下一轮开工第一步 = `ls _tmp/ tmp/` → 把上一轮
> 为同一批对象写过的脚本先原样重跑（秒级，确认数在当前版本里还成立）→ 只对本轮新出现或改过
> 的对象写新脚本。别每轮从零重写 —— 全链 776 个自写脚本里 **683 个（88%）只被用过一次**
> 就再也没人碰。复用探针 ≠ 跳过复核：探针只是取证手段，判定仍逐条对着当前版本做。

本 skill 承接 `4Coding-and-computation` 和 `7Route-diagram`。前序阶段只提供真实数据、图表 PDF 和记录文件；本阶段负责选择比赛模板、组织论文结构，并决定每张图表放入哪个章节。

## 正文编辑复核

逐项检查问题重述、材料到位状态、约束逐行排版和高密度图；按成稿页码记录证据——模板加载不代表排版合格。

### 行文用词：不用「故」，按语境写「所以／即／则」

「故」是文言式单字连词，现代技术写作按语境改：因果 → 所以；等价/换言之 → 即；推出 → 则。
（词的一部分不动：事故、缘故、无故、故事。）

### 括号只装两类东西，不许拿括号做"顺带解释"

解释类括号极易泛滥：一篇论文 **300 个括号里 226 个属解释类** —— 几乎每句都挂一个。

**允许的只有两类**：

1. 数字 / 误差：`$57.16 \pm 0.03$ h`、`（$n = 21$）`、`（$p < 0.01$）` 这类读者要用来判断的数值；
2. 附录引用：`（附录3）`、`（附表 A2）`、`（附图 A10）`。

**不许写**（逐条删或改写进句子）：

| 类型 | 反例 | 该写成 |
|---|---|---|
| 同义重复 | `末列（当前表面）最先达标` | `末列最先达标` |
| 状态说明 | `（都不收缩）`、`（都用附录3）`、`（h）` | 删（需要就写进句子） |
| 单位换算 | `极差 2.05 s（0.0006 h）` | `极差 2.05 s`（只留一个单位） |
| 指路语 | `（各式的具体形式在 5.1 中给出）` | 删（或写进正文句子） |
| 范围 / 窗口 | `（0$\sim$1800 s）`、`（一般持续 2$\sim$3 天）` | 写进句子，别塞括号 |
| 坐标说明 | `用物质坐标（初始几何距离）` | `用物质坐标` |

**判据一句话**：括号里的内容删掉后，句子仍然完整、信息不减 ⇒ 就该删。
剩下那些"删了会丢事实"的（如 `（240 个区间中温度有 95 段下降）`）去括号、把内容并进句子，
不要用括号打包 —— 括号是给读者核对用的数值留的位置，不是给作者省句子用的。

同一条也适用于图注（见「模板族与 `_base` 共享层」里那条：图注只写主体与要点）。

### 示意图必须在正文，不许往附录塞

- **正文必须有**：题意示意图（几何/边界/坐标系/机制）、求解流程图、每问的关键结果图；
- **附录只放**：写不下的推导与证明、数据表、支撑性图（完整场图、残差、收敛细节等）；
- 判据：读者不翻附录就能看懂"模型是什么、怎么解的、结论是什么"。
  三维几何示意图是"模型准备"那节的正文内容，不是附录材料。

### 数据表的两行表头：`时间` 纵跨两行 + 标题行下有局部横线

参考件的形态是：

```
                        到药材中心的距离/cm      ← 跨数据列的合并标题
时间/s   ────────────────────────────────      ← 局部横线：只走数据列，不走"时间/s"
            0     0.5     1     1.5     2      ← 子表头；"时间/s"纵跨这两行、竖直居中
──────────────────────────────────────────      ← 通栏横线
 100     28.0001 ...
```

即：两行表头（合并标题 + 子表头），标题与子表头之间有一条只覆盖数据列的横线，
行标签（`时间/s`）纵跨两行、其中心落在那条横线上。模板已为此加载 `multirow`
（见 `_base/preamble.tex` 第 50 行的注释：「时间/h 表头跨两行表头竖直居中，使其中心落在
`\cmidrule` 上」）—— 也就是说这本来就是设计意图，实现时必须做到。

**这里有个已知坑，必须按下面这个顺序试**：booktabs 的 `\cmidrule` 走 `\noalign`，在本模板的
`\fontsize{10.5pt}{12.6pt}` 下会把两行表头的行间胶一并吃掉 —— 基线距由数据行的
21.45pt 塌到 5.41pt，「到药材中心的距离/cm」与紧下的 `0/0.5/1/1.5/2` 整行叠印
（表 1～表 6 全中）。直接撤掉横线是错的：那样等于把要求的形态丢掉。

正确做法：`\multirow{2}{*}{时间/s}` + `\cmidrule(lr){2-6}`，并在 `\cmidrule` 前后
显式补出行高（`\\[2pt]` / `\addlinespace` 之类），逐页目检确认
两行表头的基线距与数据行一致、无叠印。隔离试验放 `tmp/tbltest/`。

**判据**：两行表头不叠印、行标签竖直居中、标题行下只有一条覆盖数据列的横线。
机器查不出叠印 —— 必须打开渲染出的页面亲眼看。

### 段落不要用「（一）……。」这种概括句开头

- **不许**：把段落要点先概括成一句、再加序号。两种坏法：结论式标签
  （`\textbf{（一）不是刀刃解。}`、`\textbf{（二）强稳健的结论。}`）与同义重复
  （标签那句话就是下段的内容）。
- **编号一律写成「词 + 中文序号 + 冒号」**：
  `\textbf{优点一：}`、`\textbf{缺点二：}`、`\textbf{分析一：}`、`\textbf{控制方程：}`。
  **次要的小点允许写成 `1.` `2.`** ——
  即：主要层级用「词+中文序号+冒号」，更细的并列条目用阿拉伯数字加点。
  **不许用「（一）（二）」括号编号** —— 一处都不许（`5_problem1`、`5_problem2/3/4`、
  `6_check`、`7_evaluation` 均为高发文件）。
  **标签后面不许有空格**：典型是全角空格（`\textbf{优点一　四问共用…}`，U+3000）——
  屏幕上就是「优点一」后面莫名空一块；而同一篇的「创新点一：」用的却是冒号 ⇒ 两种写法打架。
  实在想不出语义词（如灵敏度分析那几段），**干脆不写标签**也比写「（一）」强。
  改编号时先 grep 一遍按编号指路的引用（`第（三）项`、`见（二）` 这类）：
  把标签从「（四）」改成「缺点四：」之后，「由第（四）项的对照给出」就指向不存在的编号。
  引用要按内容指路，别按编号指路。
- **标签用名词短语、不带句号**：`\textbf{时间方向的离散误差：}` 可以；
  `\textbf{（一）不是刀刃解。}` 不行（那是判断句，读者要读完下一句才知道你在说什么）。
  **判据是符号，不是感觉**：段首 `\textbf{...}` /
  `\emph{...}` 的**终止符必须是全角冒号 `：`**；**以句号 `。` 收尾的一律违规** —— 那正是要禁的
  「总结的一句话」。反例：`\textbf{守恒校核。}` / `\textbf{网格与步长收敛。}` /
  `\textbf{离散化误差的量化。}`；正例：`\textbf{守恒校核：}`。
  本条已由 `python lib/web/check_skeleton.py`（`_topic_label_problems`）机械拦，写完全文跑一遍。
- **模型评价一节（优点/缺点）用中文序号的语义词**：`\textbf{优点一}`、`\textbf{优点二}` …
  然后 `\textbf{缺点一}`、`\textbf{缺点二}` …。
  写成「（一）几何约化。」…「（六）问题四的四条结构约定。」这类 ——
  全文没有一处「优点一」，读者看不出这节在讲优点还是缺点。
- 段落开头直接进入内容：结论 → 证据 → 数值，不写"这一小节说明…"。

同一条也适用于图注（见「模板族与 `_base` 共享层」里那条：图注只写主体与要点）。

## 两个"盘上本来就有一份"的登记文件：**先复用，别从零重出**

⑨ 与 ⑭ 的"章节标题 → 物理页码"映射脚本不必手写（同功能脚本重复手写会泛滥：20 份 `page-map`
归一化后只剩 2 种内容）。这两份登记都有现成工具：

| 文件 | 谁维护 | 怎么用（**别手写**） |
|---|---|---|
| `paper/page-map.json` | `python -m lib.publication map <页面区段JSON>` | 重编译后只跑这一条就重绑（按 `main.pdf` 的 SHA256）。盘上通常已有一份：`python -m lib.publication check` 说"已绑定"就直接用；说"未绑定当前PDF"就跑一次 map。**不要自己写"标题→页码"的爬取脚本** —— ⑭ 已把工具列在它的「工具」表里。硬约束一：区段按内容实际归属声明 —— 一页横跨两个类别时归前一类（或让后一类别另起一页）。声明成"整页判给后一类"会被拒绑/判 FAIL：一份 `正文 2–30` 的声明会藏住"正文实际到 31 页"，算出 30 页判 PASS、超限静默放行。**硬约束二：判据是"上一类必须真正收在自己那一页"** —— 某类别的起始页上，它的起始标记必须就是这一页最上面那块文字（`boundary_top_tol`，6pt）。只要求"落在页面前 30%"不够，**会放过漏 2–3 行的情形**（「八、」在 14.9% 处也会判过，正文仍到 31 页）—— 所以正文真的要收在自己的最后一页，别指望"差不多就行"。顺带：这条也是页数超限唯一的机械抓手 —— 字数/填充率那几条量的是"写得够不够"，量不出"多了几页"。 |
| `paper/formula-review.json` | 由本阶段与 ⑭ 共同维护 | 先看盘上那份是否仍匹配（`python -m lib.publication check` 会报）；只有公式改动过才需要更新，且在上一版的行号基准上改（别从零重新定位每个公式的物理页）。 |

## 几何表达与篇幅排版

写作前读取项目根目录 docs/PUBLICATION.md 和 config/publication.json，创建 WRITING_PLAN，分配正文预算。编译后登记全部物理页类别，执行 python -m lib.publication report；超限按删重复、迁附录、调整布局的顺序返修。应用公式样式并逐项核对数学语义，EDITORIAL_CHANGES 记录删移依据。

**篇幅目标是写满 30 页、宁多不少**（超了能压，少了是真少 —— 压缩是可逆的，写薄了没法补）。
低于 25 页会出 warning，此时补的是实质内容：建模过程、求解细节、结果分析、对照与检验、
失败结果与局限。**不许用重复段落、同一张图换角度再放一次、拆句凑行来凑页数** ——
那是灌水，评审一眼看得出来。反过来，若实在写不满，在 `WRITING_PLAN` 里写明为什么
（题面本身简单/数据量小/结论集中），不要靠排版花活填。

**但"写满 30 页"是给文字的预算，不是给"文字 30 页"的预算 —— 先给图留位。** 正文必须有的
图（题意示意图、求解流程图、每问的关键结果图，清单见 `14Layout-and-format` 的分配表）先按
预计占用扣掉，剩下的页数才是文字的额度。连锁反应是：文字把 30 页填满 ⇒
⑭ 超页 ⇒ 机械迁移把示意图赶进附录，
而示意图一旦被赶走，附录就成了它们唯一的去处。留位这一步做在写作阶段，⑭ 才不会只剩
"赶图"这一条歪路。

## 模板族与 `_base` 共享层

**本阶段只写 `sections/` 与摘要，不碰 `paper/_base/` 与 `main.tex` 的导言区** ——
那是 14Layout-and-format 的领地（见 `../14Layout-and-format/SKILL.md` 的「阶段边界」小节）。你要做的只是复制模板、然后按宏写作。

磁盘上存在的模板族：

```text
templates/zh/cumcm-latex/main.tex     # 全国大学生数学建模竞赛（电子版）
templates/zh/default-latex/main.tex   # 通用中文
```

未列出的赛事用 `zh/default-latex`，或在 `templates/zh/` 下新建一族。
新建一族很便宜：复制 `default-latex/`，只改封面/标题编号/摘要页等赛事差异，
通用排版规范全在 `_base/` 里，不必重抄。

所有模板族共享三层基础（复制模板时必须把 `_base/` 一并复制到 `paper/_base/`）：

```text
templates/_base/preamble.tex    页面/字体/行距/标题/caption/表格/浮动体/代码/断行
templates/_base/macros.tex      \papertitle \abstractcn \referencescn \appendixAcn
                                \threelinetable \papertablehalf \paperfigure
                                \paperfigurepair \paperfigurepairw
                                \paperfigurestack \appfigure
templates/_base/math-style.tex  数学字体与环境
```

`main.tex` 里是 `\input{_base/preamble.tex}` + `\input{_base/macros.tex}` + 赛事差异。

**用宏写作，不要手写环境**（format 阶段会核对）：

```latex
\paperfigure[0.85\textwidth]{fig_q1_error}{问题一预测误差分布}{q1_error}   % 单图
\paperfigurepair{a}{左图题}{lblA}{b}{右图题}{lblB}                        % 并排双图，各自编号
\paperfigurestack{a}{上图题}{tA}{b}{下图题}{tB}                           % 上下双图
\threelinetable{表 1\quad 标题}{@{}L{0.3\textwidth}L{0.6\textwidth}@{}}{表头}{表体}
```

图注只写主体与要点，一行。

参考件风格：

```
图2：圆柱形药材的几何、边界条件与轴向穿透尺度比
图3：预热平衡阶段温度的径向剖面演化
图4：预热平衡阶段水分浓度的径向剖面演化
```

即：图注说清"这张图画的是什么物理内容"，**不写图上自明的东西** ——
`左图/右图分别是什么`、`与表 N 同源`、`横轴是到中心的距离`、`色标截到多少`、
`每 180 s 一行 / 每 0.2 cm 一列` 一律不写（读者看得见图）。这些信息该去正文或表注。

`figures/manifest.json` 里登记图的 `caption` 是图的规格记录（给复核与追溯用，可以长），
不等于论文图注 —— 别把它整段抄进 `\paperfigure` 的第 3 个参数（那样会长出上百字的图注）。
判据：图注超过一行（约 40 字）就该拆。

### 图题只能是短名词短语 —— 口径披露与读数**一律不进图题**

下面是两条要求同时成立时的口径：

| 要求方 | 要什么 |
|---|---|
| 合同类/合规检查 | 「图内数字必须与正文主档区分开」——口径必须披露，不能让人误读 |
| 本节上面那条 | 图注只写主体，一行，别写图上自明的 |

两条都要满足时，容易把口径说明塞进图题，写成这种句子（反例）：

```
图 1：分析流程图；图中结果框标注的结果时长为 N=320、Δt=60 s 对照档，
       与正文主档的 57.1661 h 与 50.8238 h 不同档
图 4：问题 1 的温度场与水分浓度场：1800 s 时表面 36.79 °C、中心 33.58 °C
图 q4_effects：问题 3 与问题 4 的烘干时长对比，同为 N=320、Δt=60 s 档；
       第四档 72 h 内未达标，未入图
```

正确口径（两边都满足，不靠图题）：

```
图 1：分析流程图
图 4：问题 1 的温度场与水分浓度场
图 q4_effects：问题 3 与问题 4 的烘干时长对比
```

- **口径怎么披露**：写进图内标注（图里那条 `主档 / 对照` 文字改成实际档位，那是 ⑦ 的产物）
  或正文那一句（例如"图 4 的读数为 1800 s 时刻"）。**不写进图题**。
- **读数怎么给**：正文里给（"1800 s 时表面 36.79 °C、中心 33.58 °C，见图 4"）。
- **机械判据**：`python lib/web/check_skeleton.py` 会拦 —— 图题出现 `；`、出现 ≥2 处数字、
  或去命令后超过 40 字，一律报错并指出该挪去哪。交稿前跑一遍，别等 ⑭/⑮ 打回。
- **门禁的判词也不许反过来要求**："把档位/读数写进图题以便区分"这种 `fix` 是错的 ——
  要披露就按上面两条走（图内标注或正文）。判词给的是要求，不是范文，落地措辞服从本节。

同构的两张表要并排（参考件的表 2/3、表 4/5 即如此）。

判据不是窄，而是列结构与行数完全相同 —— 典型就是温度表与水分浓度表：
同一批时刻 × 同一批距离，只是数值与单位不同，读起来是同一张网格的两种量。
各占一个浮动体是白占约一页高度（把 4 对全拆开，足以把正文顶到超页）。

```latex
\begin{table}[htbp]
  \centering
  \begin{papertablehalf}{表 2\quad 30 分钟内药材的温度（单位：$^\circ$C）}
    \begin{tabular}{cccccc} ... \end{tabular}
  \end{papertablehalf}\hfill
  \begin{papertablehalf}{表 3\quad 30 分钟内药材的水分浓度（单位：kg/kg）}
    \begin{tabular}{cccccc} ... \end{tabular}
  \end{papertablehalf}
\end{table}
```

两半装在同一个 `table` 里、各自独立编号、各自有表题；表体直接写在环境里
（不像 `\paperfigurepair` 那样当参数传 —— 并排表的表头常是 `\multirow` + `\cmidrule`
的两行结构，塞进宏参数既难写又易错）。**列结构或行数不同的表不要并排**（会挤）——
参考件的「主要结果表 + 水分浓度表」列格式不同，就是分开排的。
这条由 `python lib/web/check_skeleton.py` 机械核。

**不要在每个 section 里手工 `\vspace` 调间距** —— 正文所有东西的间距、距离上下行、
大小必须一样，这条由 `preamble.tex` 机械保证；手工调一处就破坏一处。真需要调，交 format。

论文中的所有数值图表结论必须来自 `reports/RESULTS_REPORT.md` 或 `figures/*`。不得编造、估算或使用不同的四舍五入方式。

**经验结论必须对照最终代码输出（防"旧假设当事实抄"）**：凡论文里写的是"由代码/数据算出才知道"的结论——如某配对可行/不可行、某窗口有/无、某组能/不能达到某阈值、谁更优——在动笔前必须**对照 `code/outputs/*.json` 或 `RESULTS_REPORT.md` 的实际结果**核实，并只按最终结果写。**不得沿用建模报告（3analysis）里建模前阶段的"可能/推测/预期"句作为已定事实**；建模报告中的假设性表述若被代码结果推翻或更新，论文必须写更新后的结论（或改写为"经求解确认"），必要时删除过时推测。写完后抽查几处此类"由算才知"的断言与 outputs 一致。


## 工作流

### 步骤 0：确认排版引擎

模板族与编译方式：使用 `templates/<lang>/<竞赛>-latex/main.tex`，xelatex 编译（中文和英文均需跑两遍解决交叉引用），编译命令 `xelatex -interaction=nonstopmode main.tex`（执行两次）。

**后续步骤中的所有代码示例、文件扩展名、图片插入语法一律使用 LaTeX 版本。**

### 步骤 1：选择语言和模板


除非用户明确要求中文，否则 MCM/ICM/COMAP 一律使用英文。所有中文竞赛名称使用中文。

通用/其他赛事     -> zh/default-latex
MCM/ICM/COMAP     -> 暂无英文族（照 default-latex 新建 en/mcm-latex）
```

### 步骤 2：准备模板

用以下命令检查捆绑模板是否可访问（`SKILL_DIR` 为本 skill 所在目录）：

ls "$SKILL_DIR/templates/zh/<竞赛>-latex/main.tex" 2>/dev/null && echo "OK" || echo "MISSING"
```

- **文件存在（OK）**：建两个工程（正文一个、附录一个）——
  ```bash
  # ① 正文工程

  cp -r "$SKILL_DIR/templates/_base" paper/_base        # 别漏这行，否则 main.tex 编译不了

  cp -r "$SKILL_DIR/templates/_base" paper_appendix/_base

  ```

  > `附录A.pdf`（补充推导/图表）。`appendix/main.tex` 就是后者的入口，`\input{_base/…}`
  > 的相对路径在 `paper_appendix/` 内自洽，所以 `_base/` 要各复制一份。

### 步骤 3：构建图表规划

在写正文各节之前，根据 `figures/*.pdf`、`reports/RESULTS_REPORT.md`，以及 `reports/DRAWIO_REPORT.md`（如果存在）构建图表规划：

```text
图表规划
fig_roadmap.pdf  -> 「问题重述」之后、「问题分析」之前（= 图 1，整栏，全文唯一大图）
其余非数据图      -> 半栏以内，挨着它讲的那节（两张同构的并排放）
结果图           -> 对应的结果节
```

图 1 的位置是硬要求。参考件 `1_restatement.tex` 第 40 行就是这句，
**照它写**：

```latex
\paperfigure[0.85\textwidth]{fig_roadmap}{分析流程图}{fig_roadmap}
```

排在问题重述之后、问题分析之前（即 `1_restatement.tex` 末尾），图注就叫分析流程图。
栏宽别小于 0.85 —— 放错有两种形态：一是整张漏掉，二是塞进 `2_analysis.tex`
且缩到 `0.7\textwidth`，一张 954×1297 的竖版大图缩到七成栏宽，节点字就糊了。

它是全文唯一的大图 / 唯一带配色的图。其余流程图与示意图一律半栏以内、黑白
（见 `7Route-diagram`）；看图的人只需要一个"总览"，第二个大图只会稀释它。

两张同构的图并排放（像并排表一样）—— 参考件通篇如此，`\paperfigurepair` 用了五处
（`5_problem1` 的剖面与解析对照、`6_problem2` 的干燥曲线与剖面、`7_problem3` 的阈值穿越、
`8_problem4` 的动域几何），`\paperfigurepairw` 一处在 `7_problem3`。别各发一张整栏的，
那会白占一页高度（与表的并排同一条道理）。

特别地：数值解 / 级数解对照要拆成并排的两块，别把两个解法的四个时刻共 8 条线
塞进一张 —— 8 条线的图例会挤成"数值解 1800 s级数解 1800 s"这样连在一起读不出来。
参考件的写法是
`\paperfigurepair{q1_analytic_a}{数值解与圆柱扩散级数解的剖面对照}{…}`。

LaTeX 图片路径相对于编译工作目录：在 paper/ 内编译 main.tex 时，即使图片代码位于 sections/ 中，也使用 ../figures/xxx.pdf。

图片插入（**用宏，不要手写 `figure` 环境** —— format 阶段会核对）：

```latex
\paperfigure[0.85\textwidth]{q1_error_dist}{问题一预测误差分布}{q1_error}
```

英文论文使用英文图注。

### 步骤 4：撰写各节

**结论落地决策卡（推荐/决策/优化/预测/判定类题必备，竞赛加分项）**：凡某子问题给出了"方案/时点/阈值/分组/推荐/判定"等可执行结论，就在该问题节末尾（或 `7_evaluation` 的"推广"处）用一张速查决策卡（表格式，条件/输入 → 建议/输出）把结论浓缩成可直接操作的一张卡，让评委一眼看到"结论能直接用"。通用按题型对应：推荐/分组类给"条件→分组/时点/方案"，判定/分类类给"输入→判定/转介"，优化类给"约束→最优解"。决策卡必须只引用正文已给出的数值，不新增结论；它是"落地展示"而非"新的分析"。若本题结论天然不是"条件→建议"式的（如纯机理推导、纯证明题），可略去，但须在写作记录里说明原因。

**以下章节文件名一律使用 `.tex` 扩展名。** 例如 `1_restatement.tex`。

> **`templates/<语言>/<族名>/sections/*.tex` 是「骨架」，不是「参考」。**
> `\section{}` / `\subsection{}` / `\subsubsection{}` 的名称、层级、顺序都是给定的 ——
> 你只能往它们里面填正文，**不得新增、删除、改名、换顺序**。骨架注释里写的
> 「每个问题的分析 ≤ 3 行、全节 ≤ 一页」「条数 3--6 条，每条不长」一律是硬约束，不是建议。
>
> 骨架给定的结构如下，一律照办：
>
> | 节 | 骨架给定（不得改动） |
> |---|---|
> | 二、问题分析 | 问题一/二/三的分析 + 本文主要创新点 |
> | 三、模型假设 | **3–5 条（最多 5 条）**、每条不长 |
> | 五、模型建立与求解 | 5.1 = 问题一（具体分析/模型准备/模型建立/模型求解） |
> | 六、模型检验与分析 | 误差分析 / 灵敏度分析 |
> | 七、模型的评价与推广 | 优点 / 缺点 / 改进与推广 |
>
> **有内容放不进骨架时，把它并进骨架已有的小节，而不是另开一节。** 例：四问共用的控制方程
> 进 5.1.3 模型建立（问题一里写全），5.2.3/5.3.3/5.4.3 只写「沿用 5.1 的控制方程，仅 X 不同」；
> 而「四问共用同一套框架」这件事本身是创新点，放 2.5 本文主要创新点
> （每条 **4~5 行**、写「做了什么 + 带来什么实质改进」并引一个关键数字当证据 —— 不是每条一句，
> 那只有 2 行、撑不起这一节；篇幅与判据见下面「二、问题分析 的篇幅」那段）。
>
> **二、问题分析 的篇幅：全节 ≤ 一页半，每个问题的分析 ≤ 3 行，每条创新点 ≤ 5 行。**
> 这一节是全篇最容易写胖的地方 —— 四问分析各写成 400+ 字、加创新点就到 2205 字
> = **2.23 页**，是所有机械检查都不拦的那一类超限。
> 标尺是参考件 `基于变物性耦合传热传质与动域模型的.pdf`：它的 2.1~2.4 **各占 2~3 行**、
> 创新点**每条 4~5 行**、全节 **1.23 页**。
> 硬指标（本模板排版下 **1 行 ≈ 38 字**、**1 页 ≈ 989 字**、**一页半 ≈ 1480 字**）：
> · 每个「问题N的分析」 **≤ 3 行（≈114 字）**；
> · 每条「创新点X：」 **3~5 行（≈114~190 字）** —— 比问题分析长是对的：它要写
>   「做了什么 + 带来什么实质改进」，并引一个关键数字当证据（参考件每条都带一个）；
>   逐条量，不合并算（三条各 5 行合起来 15 行是正确写法）。
> **下限同样是硬的，别只写一句**：只写一句时所有上限都满足，于是"按新要求重写过"
>     与"把上一版原样拿来用"在机械上分不出来 —— 重跑几遍都发现不了。参考件每条 4~5 行。
>   参考件是 3 条（每条 ≈178 字）；4 条时全节约 1215 字 ≈ 1.23 页，仍在一页半以内
>   所以 **4~5 条也放得下，不必为省页数把每条压成一句**。
> · 全节 **≤ 1480 字（一页半）**，1250 字以上开始提醒。
> `python lib/web/check_skeleton.py` 会逐条核，并列出分节明细。
> **「一个数字都不写」只约束「问题N的分析」** —— 特征时间、下降百分比、倍数、量级、
> 参数明细全是结果，归第五节求解与第六节检验；写在那里既超页、又和后面重复。
> 这里只回答三件事：这一问要什么、难在哪（与其它问不同的那一处）、走什么路线。
> —— 注意 5.1 会因此变长，模板明写「**问题一不要写得特别特别长**」：只放方程与条件，
> 推导细节与实现陷阱留给 5.1.4 模型求解或第六节。
>
> **模型假设的样式**：**最多 5 条**；每条一句话
> （假设什么 + 一句依据/放宽影响），**40–70 字为宜、200 字判超**。敏感性数字、量级论证
> **不进假设节**，移到第六节检验与讨论。
>
> **排面四条（参照 `框架模板.pdf` 第 3 页「三、模型假设」，模板已按此写、照抄即可）**：
> ① 标题下先写一句引入语「为了适当地对模型进行合理简化，本文给出如下假设：」再出列表；
>    这句顶格（以 `\noindent` 开头）；
> ② 条目编号用 「假设一：/假设二：…」（中文数字），标签与冒号加粗（与「优点一：」同款），**不要项目符号**
>    （不许写成「• 假设 1」）—— 模板写的是
>    `\begin{enumerate}[label=\textbf{假设\chinese{enumi}：}]`；
> ③ 标签缩进两格、折行顶格（与正文段落同款，不是悬挂缩进）—— 缩进由 `_base/preamble.tex`
>    的全局 `\setlist[enumerate,1]` 保证（`leftmargin=0pt,itemindent=2em,labelsep=0.5em`）；
> ④ 条目之间不加空距（与正文段落一致）—— 全局 `\setlist` 已把 itemsep/parsep 清零，
>    不要自己写 `\vspace`，也不要写成「每条形如独立段落」。
>    参考件量得：引入句 x0=94.9、条目 x0=102.7、折行 x0=88.9、条目间距 19.8pt（= 正文行距）。

**各模板的章节文件名一律以该模板 `main.tex` 里的 `\input{}` 为准**——复制模板后照它列出的文件名建节即可，不必背清单。两个常用示例：

- 国赛（`zh/cumcm-latex`）正文工程：`1_restatement` `2_analysis` `3_assumptions` `4_symbols` `5_problem1…` `6_check` `7_evaluation` `A1_materials`
- 国赛附录工程（`zh/cumcm-latex/appendix/`）：只有 `A_appendix`，复制到 `paper_appendix/` 后单独编译成 `附录A.pdf`

> 两个工程、两个 PDF。正文末页是「支撑材料清单」表（`A1_materials`，由 `14Layout-and-format` 生成）；
> 详细的补充推导/图表进附录工程。源码不排进论文（`A_code` 与 `\appendixBcn` 不存在，不许再建）——

- 通用中文（`zh/default-latex`）以自己的 `main.tex` 里的 `\input{}` 为准
- MCM/ICM：英文模板族尚未提供，需要时照 `default-latex` 新建 `en/mcm-latex`（共享 `_base`，只改封面/摘要页）

子问题数不同时按 `ANALYSIS_MODELING_REPORT.md` 的子问题数量增删 `5_problemN` 节（本段第 5 章内，编号 `5.x`）。

**正文写作应使用连贯的学术段落。避免在最终论文中出现工作流内部名称，如 `reports/`、`figures/` 或 `CLAUDE.md`。**

| 不要这样（注水） | 改成 |

四条硬判据：**① 括号里不出现「问题一/二/三/四」（上下文已说明）；② 不出现「单位：」**
（改用 `量 / 单位` 的标准写法）；③ 同一数字不在括号里再换算一遍（"X h（Y 天）"）；
**④ 括号里不出现「而非…」「一律…」「只在…成立」「…档」这类补充/限定/对比小句**。
另外 —— **不得复述题面已给的条件**（"一般持续 2~3 天"是题面原话），那是「问题重述」的活。

### 步骤 5：参考文献

只使用真实存在的参考文献。参考文献写在 `paper/references.tex`。

**全表 8–12 条**（与 ⑫ 评分标的「8–12 篇」一致）。超过 12 条就停手：
剩下的引用需求靠合并同类项或改写成本句直接陈述（口径、定义、常识性结论不必逐条给文献），
不要为凑覆盖面加条目、更不要拆条凑数；不足 8 条则说明调研确实不够，回去补真文献（不许补造）。
**每条都必须被正文 `\cite` 引用**，没被引的删掉；正文也不许出现文献表里没有的引用。

**每条带 DOI 或可访问链接**：从 1Literature-orientation 的检索记录继承 DOI/URL，无 DOI 的给期刊/会议官网（含页码），**禁止裸条目**；拿不到可核验信息就删/换，**不许补造 DOI**。写完用 norms「算法可复现细节」核对一遍：凡引了元启发/迭代算法（DE 等），正文或附录是否给了超参与复杂度（从提交代码抄真实值）。

### 步骤 6：最后撰写摘要或总结

在所有章节完成后撰写中文摘要或英文 Summary Sheet。必须包含每个子问题的方法和精确的数值结果。

摘要写在 `main.tex` 的 `\abstractcn{…}` 里（不在 `sections/` —— 返修轮次只改 `sections/` 时最容易把摘要整个漏掉）。**写完必须量**：`cd paper && xelatex -interaction=nonstopmode main.tex` 两遍 → `python -m lib.publication report` → 读 `min_kind_fill` 的 `fill` 与 `rows`（`rows` = 还差几行），不够就按行数补实质内容再量一遍，直到 ≥0.90 或确认已经写无可写（写无可写时把差值写进 `WRITING_PLAN` 的说明，别默默收工）。

**公式写法纪律 · 第三条**：**多行 display 一律 `gather`，禁止 `equation` 套 `aligned`**：`aligned` 把整块包成一个盒子 ⇒ 公式后的净空被吃到 **−8.4pt**（压下一行正文）；换 `gather` 为 **+13.8pt**，末行再改平（别带 `\frac`）**+19.0pt**。**别按环境名一刀切**（三行的 `aligned` 是 +11.1/+13.3pt 正常）—— 收尾用 `python -m lib.publication check` 量几何净空（判据已机械化为「< 3pt 判失败」）。手改治横向超栏时改成 aligned 的式子，修回 gather 时会被漏下（见 `reports/EDITORIAL_CHANGES.md`）⇒ 别再手改写法，按纪律写。

公式写法纪律（两条硬规矩，成因与量测见 `docs/WRITING_QUALITY.md`「公式的三种间距」）：① 公式紧跟引出它的那句话，中间不留空行 —— 空一行公式就自成一段，`\abovedisplayskip` 完全失效，净空从 13pt 变成 23pt 以上；② 连着写的多个公式合成一个 `gather`（每行一条、`\\` 换行、`\label` 留在自己那行），不要写成多个 `equation`、更不要在它们之间留空行 —— 公式↔公式的净空：三个 equation 加空行 53.5/45.9pt，删空行 26.0/33.5pt，**合成一个 gather 21.6/18.7pt**（与"公式↔文字"的 20pt 同档）。gather 逐行编号，编号与原来逐个 equation 相同，引用不受影响。

摘要与关键词纪律：CUMCM 摘要页**限 1 页、而且必须写满这一页**。**硬指标 = 版心填充率 ≥ 0.90**，用 `python -m lib.publication report` 的 `min_kind_fill` 核（它按本文实际版心量，不靠字数估算）；**< 0.80 会被 ⑪ 判死并回退到本阶段重写**。标尺：参考稿 92.7%，78.4% 即判"少"。按本模板版面 0.90 ≈ 整页 1050 个非空白字符。写满的办法是加实质内容（每问的方法要点 + 结论数字 + 该问的检验/灵敏度），不是放大字号/加行距；「850–950 字内安全」读起来是上限、与本节口径不符，**别再按它写**。关键词 ≤6 个、单独一行，别让最后一行只剩一两个字，且每个都要"本题特有"：题面对象 / 本文模型特征 / 本文真用的关键方法。拒绝"任何论文都能写"的通用词（灵敏度分析、数值模拟、优化分析、数学建模 之类，属凑数）；优选具体短语（`动域与材料坐标` > `材料坐标`、`阈值求根` > `事件定位`）。参照件样例：热风干燥；变物性耦合传热传质；有限体积法；动域与材料坐标；阈值求根。字数/内容规范见 norms「摘要写作要点」。

假设节纪律见 norms「假设节编制纪律」——假设只收"建模约定"（题面给定与物理必然不放节），**最多 5 条**，**且每条控制在 1.5–2 行（约 55–80 字）**：一句话"假设什么" + 一句话"为什么可以"，量化影响（"放宽后位移 3 h"这类）挪到正文或附录。**6 条全是 3 行的写法不合格，每条要压到 1.5–2 行。**
